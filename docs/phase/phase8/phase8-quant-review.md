## 항목별 검증 결과

### 1. Sprint 1·2 (신호 품질) ✅

- 기존 Phase 7.2 확정 파라미터(2026-04-17) 승계 — 통계적 근거 이미 검토 완료
- momentum_score 스케일 `min(pct/7.0, 1.0) * 0.7` — prev_close 돌파의 낮은 기준점을 보정하는 적정 설계
- confidence 상한 0.75 (prev_close), 0.85 (gap_open) — 과도 신뢰 방지 적정

### 2. Sprint 4 (성과 분석) ✅

- **주의사항**: MDD는 **고점 대비** 계산이 표준. "초기 자본 대비"로 구현하면 상승장에서 실제 손실과 괴리.
- Sharpe 비율 계산 시 **무위험 수익률** 필요. 한국 기준 KOFR(기준금리 3.5%) 사용 권고.
- **표본 크기 경고**: 1개월 미만 운영 데이터로 Sharpe/MDD 계산은 **통계적 의미 없음**. UI에 "표본 ≥ 30거래일" 표시 필수.

### 3. Sprint 5 (5분봉 가속도) ⚠️

**핵심 이슈**: Phase 9 재검토에서 "KIS 과거 분봉 백필로 Z-score 조기 활성화 가능"이 확인되면, Phase 8 Sprint 5의 "데이터 수집 시작"만으로 분리할 이유가 없어진다.

**재편성 권고**:
```
[기존] Phase 8 Sprint 5: 가속도 지표 + DB 수집 인프라
       Phase 9 Sprint 1: Z-score (20거래일 축적 대기)

[제안] Phase 8 Sprint 5: 삭제 또는 Phase 9로 이관
       Phase 9 Sprint 0: DB 수집 인프라 + KIS 백필
       Phase 9 Sprint 1: Z-score + 가속도 지표 통합
```

**이유**:
- 가속도 지표와 Z-score 둘 다 5분봉 거래량 기반 — 지표 상관관계 매우 높음
- 통합 설계 시 팩터 중복 제거, confidence 프레임워크 재설계 한 번에 가능
- 분리 구현 시 confidence 가중치 재조정이 2번 필요 (유지보수 비용 증가)

### 4. 김단타 지적 (가속도 시간대 가중) 의견 동의

- 09:30 이전, 14:30 이후 비활성화 합리적
- 점심시간 가중치 축소는 **실증 데이터로 검증** 후 확정 권고. 초기값 0.3은 과소 가능.

## 리스크 및 대안

1. **Sprint 5 삭제 시 영향**: Phase 8 범위 축소 → 일정 단축. Sprint 3·4에 집중 가능.
2. **Phase 9로 이관 시 리스크**: DB 수집 인프라 구축 타이밍이 Phase 9 Sprint 0으로 밀림. 즉, Phase 8 배포 후 Phase 9 착수 전까지 5분봉 DB 영속 저장 없음 → 데이터 축적 시작이 Phase 9 착수 시점에 달림.
   - **대안**: Phase 8에 **경량 Sprint 5** (DB 수집 인프라만) 남기고, Z-score/가속도 지표는 Phase 9로 이관. 이는 데이터 축적 시작을 앞당기는 이점.

**최종 권고**: 대안 채택 — **Phase 8 Sprint 5는 "시간대별 DB 수집 인프라 + VWAP 틱 누적" 만으로 축소**, 가속도 지표 계산은 Phase 9로 이관.
