## 범위 및 목적

Phase 6.1에서 구축한 5분봉 거래량 수집 파이프라인의 축적 데이터를 기반으로, **5분 단위 거래량 가속도 지표**를 구현하여 `momentum_breakout` 전략의 confidence 가중치에 반영한다.

### 핵심 아이디어

- **거래량 가속도**: 최근 5분봉 거래량이 직전 5분봉 대비 증가하고 있는지(가속), 감소하고 있는지(감속) 판별
- 가속 중인 종목 = 시장 관심 증가 중 → confidence 상향 가중
- 감속 중인 종목 = 관심 감소 중 → confidence 하향 가중 또는 필터 아웃
- 김단타 권고: "틱/5분봉 기반 거래량 가속도가 있어야 단타에서 실제 의미 있는 신호"

## 필요 선행 데이터

| 데이터 | 소스 | 스키마 | 최소 축적 기간 |
|--------|------|--------|--------------|
| 5분봉 거래량 | Phase 6.1 `vol5m:*` Redis 키 | `vol5m:{code}:{date}:{slot}` → `{buy_vol, sell_vol, total_vol, trade_count}` | **20거래일** (약 4주) |

### 착수 조건 체크리스트

- ⬜ Phase 6.1 완료 및 프로덕션 배포
- ⬜ 5분봉 수집 파이프라인 정상 동작 확인 (3거래일 이상 무결)
- ⬜ `vol5m:*` 키에 **20거래일 이상** 데이터 축적
- ⬜ 축적 데이터 품질 검증: 결측 슬롯 비율 < 5%

### 착수 경고 기준

**`vol5m:*` 키에 20거래일 미만 데이터가 축적된 상태에서 착수 지시가 오면 AI가 경고 발생.**

경고 내용:
- 현재 축적 거래일 수 (예: "현재 12거래일분 데이터 축적")
- 최소 필요 수준: 20거래일
- 착수 시 리스크: 통계적 유의성 부족, 가속도 지표 과적합 가능성
- 권장 대기 기간: 잔여 거래일 수

## 이 Phase 내 후속 Phase용 선행 구축

Phase 8에서 **동시간대 N일 거래량 Z-score**를 구현하려면 시간대별 거래량의 **DB 영속 저장**이 필요하다. Redis TTL 30일은 충분하지 않으므로, 이 Phase에서 다음을 구축한다:

- **시간대별 거래량 DB 테이블** (`volume_5min_history`): stock_code, date, slot_index, buy_vol, sell_vol, total_vol, trade_count
- **EOD 배치 작업**: 장 마감 후 당일 Redis 5분봉 데이터를 DB로 이관
- **VWAP 틱데이터 수집 시작**: 체결 데이터(가격 x 거래량)를 Redis에 슬롯별 누적, Phase 8에서 사용
