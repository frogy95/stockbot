## 검토팀 확정 파라미터 (2026-03-29)

> **검토 참여**: 정프로(PO), 최리스크(리스크관리), 윤에이피(API 개발자), 김단타(단타 전문가)

### API 검증 순서 및 비중

| 항목 | 원래 설계 | 확정값 | 근거 |
|------|----------|--------|------|
| 검증 순서 | 미정 | 한투 > 텔레그램 > 네이버 > DART | 정프로: 핵심 의존성 순서, 한투가 프로젝트 성패 좌우 |
| Sprint 수 | 1개 | **1개 유지** | 정프로: 탐색 Phase에 분할 불필요 |
| 스크립트 형식 | Jupyter/Python 혼용 | **Python 스크립트 기본 + Notebook 보조** | 윤에이피: 재실행성 우선, 응답 분석은 Notebook 가능 |

### 한투 API 검증 항목 (확장)

| 항목 | 원래 설계 | 확정값 | 근거 |
|------|----------|--------|------|
| 시세 조회 범위 | 현재가, 호가 | **현재가 + 호가(10단계) + 체결강도 + 거래량비율 + 분봉** | 김단타: 단타 전략의 기본 데이터 |
| 호가 검증 | 호가 조회 | **10단계 잔량 + 총잔량 + 갱신 빈도** | 김단타: 호가 품질이 전략 기반 |
| 추가 검증 | 없음 | **hashkey, tr_id 매핑, 호가단위, 장상태, WS암호화, 인코딩** | 윤에이피: 문서와 실제가 다른 핵심 포인트 |
| 에러 시나리오 | 미포함 | **필수 포함 (5가지)** | 최리스크: 정상만 검증하면 실전 장애 |
| 웹소켓 테스트 | 30분 연결 유지 | **30분 유지 + 데이터 지연 측정 + 끊김 재연결** | 김단타+최리스크: 지연과 안정성 모두 중요 |
| Rate Limit 테스트 | 실측만 | **실측 + 초과 시 응답 코드 + 복구 시간** | 최리스크: 스로틀링 설계 근거 |
| 장중 테스트 | 미언급 | **반드시 장중(09:00~15:30) 포함** | 김단타: 장외 데이터와 장중 데이터가 다름 |

### 네이버 API 검증 기준

### Task 1: 한국투자증권 API 검증

**우선순위**: 최고 (프로젝트 핵심 의존성)

#### 검증 항목

| # | 항목 | 스크립트 | 성공 기준 |
|---|------|---------|----------|
| 1 | OAuth 토큰 발급 | `01_auth.py` | access_token 수신, 유효기간 확인 |
| 2 | 현재가 조회 | `02_stock_price.py` | 삼성전자(005930) 현재가 + 거래량 반환 |
| 3 | 호가(10단계) 조회 | `03_orderbook.py` | 매수/매도 각 10단계 호가 + 잔량 |
| 4 | 체결강도/거래량 | `04_trade_volume.py` | 체결강도, 전일대비 거래량 비율 확인 |
| 5 | 모의 주문 실행/취소 | `05_order_test.py` | 주문 접수 -> 주문번호 -> 취소 왕복 성공 |
| 6 | 웹소켓 실시간 시세 | `06_websocket.py` | 30분 연속 수신 + 데이터 지연 < 1초 |
| 7 | Rate Limit 실측 | `07_rate_limit.py` | 초당 허용 건수 측정, 초과 시 응답 코드 기록 |
| 8 | 에러 시나리오 | `08_error_scenarios.py` | 5가지 에러 시나리오 응답 구조 기록 |
| 9 | 기타 검증 | `09_misc.py` | hashkey, tr_id, 호가단위, 장상태, WS암호화, 인코딩 |

#### 에러 시나리오 상세 (최리스크 필수 요구)

1. **잘못된 종목 코드** → 응답 코드, 에러 메시지 구조
2. **만료된 토큰** → 응답 코드, 자동 갱신 트리거 가능 여부
3. **Rate Limit 초과** → HTTP 상태 코드, 복구까지 대기 시간
4. **웹소켓 강제 끊김** → 재연결 시 구독 복원 필요 여부
5. **장 외 시간 호출** → 시세/주문 각각의 응답 차이

#### 장중 테스트 필수 항목 (김단타 요구)

- 웹소켓 실시간 시세는 **반드시 장중(09:00~15:30)**에 테스트
- 시초가 시점(09:00~09:30) 데이터 폭주 시 지연 측정
- 장마감 시점(15:20~15:30) 동작 확인
