## 2. 항목별 검증 결과

### ⚠️ 한투 시세 조회 — 체결 강도 확인 필수
- 현재가 조회는 기본이나, **단타에 핵심적인 데이터**가 포함되는지 확인 필요:
  - **체결 강도** (매수/매도 체결 비율)
  - **거래량 급증 여부** (전일 대비 거래량 비율)
  - **프로그램 매매 수급**
  - **시간대별 체결 데이터** (분봉/틱)
- 이 데이터가 없으면 스크리닝/전략 설계에 심각한 제약

### ❌ 한투 호가 데이터 — 검증 항목 부족
- 현재 계획에 "호가 조회"만 있으나, 실전에서 중요한 것은:
  - **10단계 호가** 잔량 데이터의 정확성
  - **호가 갱신 빈도** (웹소켓 vs REST 차이)
  - **호가 총 잔량** (매수/매도 잔량 불균형)
- "거래량이 모든 것의 기반" — 호가/체결 데이터 품질이 전략의 기반

### ⚠️ 한투 웹소켓 실시간성 — 지연 측정 필수
- 30분 연결 유지도 중요하지만, **데이터 지연**이 더 중요
- "타이밍이 전략보다 중요" — 실시간 데이터가 0.5초 지연되면 단타에 치명적
- 측정 항목:
  - REST 시세 vs 웹소켓 시세의 시간 차이
  - 웹소켓 데이터 수신 간격 (체결 빈도 높은 종목 기준)
  - 장 시작 시점의 데이터 폭주 시 지연

### ⚠️ 네이버 뉴스 — 단타 활용 가능성 낮을 수 있음
- 뉴스 센티멘트는 단타보다 스윙에 유용
- 단타에서 뉴스가 유용한 경우는 **속보성 재료** (공시, 이슈)
- 네이버 뉴스 API가 "속보"를 얼마나 빠르게 반영하는지가 핵심
- 1시간 이상 지연되면 단타에는 무의미

### ✅ DART — 단타 무관 결론 예상
- 재무정보/공시는 중장기 투자에 유용, 단타에는 직접적 활용 어려움
- 다만 **당일 공시** (유증, 자사주, 실적 발표)는 급등락 촉발 — 이 부분만 확인
- 실시간 공시 알림이 가능한지 확인하면 충분

### ✅ 텔레그램 응답 속도 — 적절
- 승인 요청 -> 사용자 응답 -> 주문 실행 전체 지연이 3초 이내면 충분
- "장 시간대별 특성 존중" — 시초가 30분은 승인보다 자동이 나을 수 있음 (Phase 3에서 논의)

## 3. 파라미터 조정 권고

| 항목 | 원래 설계 | 권고값 | 근거 |
|------|----------|--------|------|
| 한투 시세 검증 항목 | 현재가/호가 | 현재가 + 체결강도 + 거래량비율 + 분봉 | 단타 전략의 기본 데이터 |
| 호가 데이터 검증 | 호가 조회만 | 10단계 호가 + 잔량 + 갱신 빈도 | 호가 품질이 전략 기반 |

| 장중 테스트 | 미언급 | 반드시 장중(09:00~15:30) 테스트 포함 | 장 외 데이터와 장중 데이터가 다름 |

## 4. 리스크 및 대안

| 리스크 | 영향 | 대안 |
|--------|------|------|
| 체결 강도 데이터 미제공 | 높음 | 체결 데이터에서 직접 계산하는 방안 검토 |
