## Phase 1 설계 반영 사항

### 1. 한투 API 토큰 관리

- **토큰 발급 Rate Limit**: 1분당 1회 → Redis에 캐싱, 만료 10분 전 자동 갱신
- **유효기간**: ~24시간 → 스케줄러로 일 1회 갱신

### 2. 한투 API Rate Limit 스로틀링

- **공식 한도**: 초당 1건 (모의), 초당 ~20건 (실전)
- **실측**: 모의에서 0.1초 간격도 일부 허용되나, 연속 호출 시 차단 발생
- **설계**: 모의 **1.5초 간격**, 실전 공식 한도의 **70%**(초당 14건) 적용
- **구현**: 토큰 버킷 또는 슬라이딩 윈도우 스로틀러

### 3. 에러 핸들링 전략

- **잘못된 종목**: HTTP 200 + 빈 데이터 → `stck_prpr == "0"` 등 **데이터 값 검증 필수**
- **만료 토큰**: HTTP 500 + `EGW00121` → 자동 재발급 후 재시도
- **Rate Limit**: `초당 거래건수를 초과` 메시지 → 백오프 후 재시도
- **장외 주문 거부**: rt_cd=1 + 메시지 확인 → 장 상태 사전 체크 필요

### 4. 웹소켓 전략

- **기본**: 웹소켓 실시간 시세 사용 (재연결 시 재구독 필요)
- **재연결**: 0.016초로 매우 빠름 → 자동 재연결 + 재구독 로직 구현
- **폴백**: 웹소켓 불안정 시 REST 폴링 (1.5초 간격)
- **장중 테스트 후 최종 결정** (30분 안정성, 지연 측정)

### 5. 텔레그램 메시지 형식

- **HTML 형식 권장** (MarkdownV2는 이스케이프 복잡)
- **지연 0.5초**: 실시간 알림 충분
- **인라인 버튼**: 승인/거부/보류 3버튼 레이아웃 확정

### 6. 네이버 API 활용 범위 축소

- **원래 계획**: 속보 + 센티멘트
- **조정**: 센티멘트 분석만 활용 (대형주 외 속보 반영 1시간+)
- **Phase 2 영향**: 뉴스 센티멘트 스코어링은 보조 팩터로만 사용

### 7. DART API 활용 범위 축소

- **원래 계획**: 재무 + 실시간 공시
- **조정**: 재무 데이터만 활용 (실시간 공시 지연 불확실)
- **Phase 2 영향**: 스크리닝에 재무 기초 데이터(매출, 영업이익)만 활용
- **corp_code 매핑**: 사전 구축 필요 (종목코드 → DART corp_code)

### 8. ETF 처리 전략

- **시가총액**: 공공데이터포털에서 미제공 → 한투 API 시세 × 상장주식수로 계산
- **재무정보**: DART에서 미제공 → ETF는 재무 팩터 제외
- **호가단위**: 5원 고정 (가격 무관)
- **FID_COND_MRKT_DIV_CODE**: KOSPI/KOSDAQ/ETF 모두 `J`

### 9. 장전 스크리닝 데이터 수집 전략 (핵심 변경)

- **1차 스크리닝 소스**: 공공데이터포털 (한투 REST 아님!)
- **이유**: 한투 REST로 2,880종목 개별 호출 시 모의 72분, 실전 3.4분 소요. 공공데이터포털은 6회 호출로 전 종목 수집
- **수집 흐름**:
  1. 장전 08:00 — 공공데이터포털 6회 호출 → 전 종목(2,880개) 종가/시가/고가/저가/거래량/시총 DB 저장
  2. DB 기반 1차 스크리닝 → 후보 종목(수십 개) 선정
  3. 장중 09:00~ — 한투 REST/WS로 **후보 종목만** 실시간 모니터링 + 2차 동적 스크리닝
- **Rate Limit**: 일 1,000회 중 6회만 사용 → 여유 충분
- **ETF**: 공공데이터포털 미제공 → 한투 REST로 개별 조회 (ETF는 수십 종목이므로 Rate Limit 문제 없음) 또는 별도 API 활용 신청
- **DART 재무**: corp_code 매핑 사전 구축 필요 (corpCode.xml → DB). 에코프로비엠 corp_code `01160363` 확인

### 10. DART corp_code 매핑

- **문제**: DART API는 종목코드가 아닌 corp_code 사용. 매핑 없으면 재무 조회 불가
- **해결**: `corpCode.xml` (3.5MB) 다운로드 → 종목코드-corp_code 매핑 테이블 구축
- **시점**: Phase 2 Sprint 1에서 구축, 이후 주기적 갱신
