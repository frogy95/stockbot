## 2. 항목별 검증 결과

### ✅ 모의거래 검증 범위 적절
- 시세 조회 + 주문 왕복 확인은 Phase 1 설계의 전제 조건
- 웹소켓 30분 연결 유지 테스트도 적절한 기준

### ✅ Rate Limit 실측 포함
- 모의거래 공식 초당 1건 vs 실제 허용치를 실측하는 것은 필수
- Phase 1 스로틀링 설계의 근거 데이터

### ❌ 에러/장애 시나리오 검증 누락
- **최악의 시나리오를 기준으로 설계해야 함**
- 현재 계획에는 정상 케이스만 포함, 비정상 케이스 검증이 없음
- 필수 추가 항목:
  - 잘못된 종목 코드로 주문 시 응답
  - 토큰 만료 후 API 호출 시 응답
  - Rate Limit 초과 시 응답 코드 및 복구 시간
  - 웹소켓 강제 연결 끊김 후 재연결 동작
  - 장 외 시간 API 호출 시 동작

### ⚠️ .env 보안 관리
- API 키/시크릿이 .env에만 존재하는지 확인 절차 필요
- `.gitignore`에 `.env` 포함 확인 (이미 있으나 재확인)
- 탐색 스크립트에 하드코딩 방지 가이드라인 필요

| 항목 | 원래 설계 | 권고값 | 근거 |
