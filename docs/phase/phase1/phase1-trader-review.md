## 2. 항목별 검증 결과

### 미확정 항목 #1: 데이트레이딩 vs 스윙

**동의: 데이트레이딩 전용**

- 단타 전략의 기본은 당일 청산이다. 오버나이트는 다른 게임이다.
- 자동 시스템이 오버나이트 포지션을 들고 있으면 장전 갭에서 손절이 밀린다. -2% 손절을 설정해도 -5% 갭다운이면 속수무책.
- **단, 15:20 강제 청산은 시장가로**: 잔여 호가에 물량이 없으면 슬리피지가 크다. 15:15부터 단계적 청산(잔여 물량의 50% -> 75% -> 100%) 권고.

### 한투 API 연동 의견

- Phase 1에서 **주문 실행은 REST만** 사용. 웹소켓 주문은 복잡도만 높이고 실익이 적다.
- 웹소켓은 **시세/호가/체결 수신 전용**으로 한정.
- 모의거래 체결 로직이 실전과 다르다는 점을 **코드 주석과 문서에 반복 명시**해야 한다. 나중에 실전 전환할 때 가장 큰 함정이다.

### 손절/익절 기준값 (최리스크와 공동)

- 최리스크의 **-2% 손절, +3% 익절** 동의.
- **추가 권고**: 트레일링 스탑 구현 필수. 주가가 +2% 올랐다가 내려오면 +1%에서 익절하는 것이 단타의 핵심. 고정 익절만으로는 수익을 극대화할 수 없다.
- 트레일링 스탑 파라미터: 고점 대비 **-1%** 하락 시 청산 (Phase 3에서 구현, Phase 1에서 settings에 필드 포함).

## 4. 리스크 및 대안

- **리스크 1**: 시초가 매매 금지를 나중에 해제할 때 별도 전략이 필요하다. Phase 1에서 시간대별 매매 허용/금지를 settings에 저장하는 구조를 미리 설계.
- **리스크 2**: 15:20 강제 청산 시 거래량이 적은 종목은 체결이 안 될 수 있다. **15:15부터 미체결 시 호가 단계적 하향** 로직이 Phase 3에서 필요.
- **리스크 3**: 모의거래에서 승인 타임아웃 30초를 테스트하기 어렵다 (체결이 안 되므로). 타임아웃 로직만 단위 테스트로 검증.
