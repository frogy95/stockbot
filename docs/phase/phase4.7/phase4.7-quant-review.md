## 2. 항목별 검증 결과

### 2.1 버그의 통계적 분석

현재 `_calc_percentiles()`는 순위 기반 백분위(rank percentile)를 계산한다:
- `percentile = rank / total * 100`
- 분산=0인 팩터 → 모든 종목 동일 rank=1 → percentile = 1/N * 100

44개 종목일 때:
- trade_strength: 전부 50.0 → percentile = 2.27%
- orderbook_ratio: 전부 1.0 → percentile = 2.27%
- 이 두 팩터의 가중치 합 = 0.4 (전체의 40%)
- 최대 기여: 2.27 * 0.4 = **0.91점** (40% 가중치에서 0.91점만 기여)
- 유효 팩터(3개) 최대 기여: 100 * 0.6 = **60.0점**
- 따라서 이론적 최대 스코어 = **60.91점** < 임계값 80.0

**결론**: 구조적으로 절대 통과 불가. 이것은 파라미터 조정이 아니라 아키텍처 결함.

### 2.2 B안 기각의 통계적 근거

percentile=50을 "중립"으로 부여하는 것의 문제:
1. **정보 없음 ≠ 중간**: 체결강도/호가잔량 데이터가 없는 것은 "중간 수준"이 아니라 "모른다"
2. **편향 주입**: 실제 분포와 무관한 50을 넣으면, 나머지 3팩터의 상대적 영향력이 왜곡됨
3. **가중치 실질 변환**: 5팩터 중 2개가 고정 50이면, 실질적으로 3팩터 스코어에 상수 20을 더하는 것 (50 * 0.2 * 2 = 20). 이것은 A안의 3팩터 * 1/3 가중치와 수학적으로 다른 결과를 낸다.

수학적 증명:
- B안: score = sum(3팩터 * 0.2) + 50*0.2 + 50*0.2 = sum(3팩터) * 0.2 + 20
- A안: score = sum(3팩터) * 0.333

100점 만점에서 B안의 최대 = 60 + 20 = 80 (임계값과 동일, 경계값 문제)
A안의 최대 = 100 (명확한 상한)

### 2.3 FactorScorer 일관성 유지 방안

`FactorScorer` 클래스 자체는 변경 최소화:
- 생성자에 `factors` 파라미터 추가 → 스코어링 대상 팩터 지정
- 기본값은 기존 `STOCK_FACTORS` 유지 (하위 호환)
- 1차 스크리닝은 `PRIMARY_STOCK_FACTORS = [volume, volatility, momentum]`
- 2차 스크리닝은 기존 `STOCK_FACTORS` (5팩터) 유지

## 3. 파라미터 조정 권고

| 항목 | 원래값 | 권고값 | 근거 |
|------|--------|--------|------|
| 1차 팩터 리스트 | STOCK_FACTORS (5개) | **PRIMARY_STOCK_FACTORS (3개)** | 정보량 있는 팩터만 사용 |
| 1차 가중치 | 각 0.2 | **각 ~0.333** (1/3) | 3팩터 균등 — 단순성 원칙 |
| 1차 pass_threshold | 80.0 | **60.0** | 3팩터 백분위 평균 60 이상 = 상위 40%. 단, 운영 데이터로 보정 필요 |
| 2차 pass_threshold | 80.0 | **75.0으로 소폭 하향 검토** | 초기 운영 데이터 확보를 위해 |
| ETF 1차 팩터 | ETF_FACTORS (5개) | **PRIMARY_ETF_FACTORS (3개)** | 동일 논리. tracking_error도 1차에서는 NAV 없어 의미 없음 |

### 3.1 가중치 커스터마이징 여부

현재 3팩터 균등(1/3)이 가장 단순하고 과적합 위험이 적다. 향후 운영 데이터 축적 후:
- 각 팩터의 예측력(IC, Information Coefficient) 측정
- IC 비례 가중 또는 최적화 검토
- 단, 파라미터가 많을수록 과적합 → 초기에는 균등이 최선

| momentum_factor 0.0 반환 (데이터 부족) | closes < 4일이면 0.0 → 동률 발생 가능. 단, 3팩터 중 1개만이므로 나머지로 차별화 |
| volatility_factor 0.0 반환 (데이터 부족) | highs < 2일이면 0.0. 신규 상장/IPO 종목에서 발생 가능. 경고 로깅 권장 |
