## 2. 항목별 검증 결과

### MVP 범위 적합성
- 이 Phase는 **프로덕션 장애 대응**으로, Phase 5 전 필수 안정화 작업
- 범위가 명확하고 좁음 — 단일 Sprint로 충분
- 새로운 기능이 아닌 기존 로직의 복원력 강화이므로 빠른 배포 가능

### Sprint 분할
- **단일 Sprint 적합**: 변경 범위가 scheduler.py + validator.py 2개 파일 중심
- 프론트엔드 변경 없음 — 백엔드 전용
- 1~2일 내 완료 가능한 규모

### 재시도 후 스크리닝 재실행
- **핵심 가치**: 08:30 포털 재시도 성공 시 primary_screen 자동 재실행은 반드시 필요
- 현재 체인 구조에서 08:30 재시도는 독립 CronTrigger — 재시도 성공해도 스크리닝이 이미 "skipped" 상태
- 이 갭을 메우는 것이 이번 Phase의 핵심 가치 중 하나

## 5. 최종 의견

**승인**. 긴급 수정 성격에 맞는 좁은 범위, 단일 Sprint. 핵심은 "DB에 데이터가 있으면 스크리닝을 차단하지 말 것"이라는 단순한 원칙이며, 이를 안전하게 구현하는 것이 목표. 재시도 성공 후 스크리닝뿐 아니라 후속 단계(dart, sentiment)도 재실행 범위에 포함해야 완전한 복구가 됨을 주의.
