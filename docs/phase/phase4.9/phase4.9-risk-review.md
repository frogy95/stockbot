## 2. 항목별 검증 결과

### DB 기반 의존성 전환
- 방향 자체는 올바름 — 파이프라인 상태보다 실제 데이터 존재 여부가 더 신뢰할 수 있는 지표
- **단, DB 데이터 신선도(freshness) 검증이 핵심**: T-1 데이터와 T-3 데이터는 완전히 다른 품질
- T-2까지 허용하는 것은 보수적으로 수용 가능하나, **T-2 데이터 사용 시 반드시 경고 필요**

### 이중 실패 + DB 데이터 존재 시 스크리닝 진행
- **가장 위험한 시나리오**: 당일 수집이 모두 실패했는데 과거 데이터로 스크리닝하는 것
- DB에 T-1 데이터가 있더라도, 그 데이터가 "어제의 수집" 결과일 수 있음
- 이 경우 스크리닝은 진행하되, **매매 신호 생성은 제한해야 함**
- pipeline_healthy는 수집 실패 상태를 유지해야 — 스크리닝은 되지만 자동 매매는 차단

### pipeline_healthy 플래그 처리
- 초안에서 "DB 폴백 시 pipeline_healthy = true (조건부)"라고 했는데, **이건 위험**
- **pipeline_healthy는 "당일 수집이 정상 완료됨"을 의미**해야 함
- DB 폴백으로 스크리닝이 진행되더라도, 수집 자체가 실패했으면 healthy가 아님
- **권고: pipeline_healthy와 screening_ready를 분리**
  - pipeline_healthy: 수집 상태 (기존 로직 유지)
  - screening_ready: DB 데이터 충분성 (신규)

## 3. 파라미터 조정 권고

| # | 항목 | 초안값 | 권고값 | 근거 |
|---|------|--------|--------|------|
| 1 | DB 데이터 충분성 임계값 | 1500건 | **1500건 유지** | Phase 4.6에서 확정된 값과 일관성 유지 |
| 2 | 허용 데이터 날짜 범위 | T-2 이내 | **T-1 우선, T-2는 경고 수반** | T-2 데이터는 품질 저하 가능. T-1이면 정상, T-2이면 warning 알림 |
| 4 | DB 폴백 시 pipeline_healthy | "true" (조건부) | **"false" 유지 — screening_ready 별도 플래그** | 수집 실패 시 healthy를 true로 바꾸면 자동 매매가 활성화됨. 절대 불가 |
| 6 | 이중 실패 + DB 데이터 시 스크리닝 | 진행 (경고 포함) | **스크리닝 진행 + pipeline_healthy=false 유지 + 텔레그램 긴급 알림** | 스크리닝은 허용하되 자동 매매는 차단. 반자동 모드에서만 사용 가능 |
| 7 | DB 데이터 null_ratio 임계값 | 5% | **5% 유지** | Phase 4.6 확정값 일관성 |

## 4. 리스크 및 대안

| 리스크 | 심각도 | 대안 |
|--------|--------|------|
| DB 폴백으로 스크리닝 성공 → pipeline_healthy=true → 자동 매매 진행 → 오래된 데이터로 매매 | 🔴 High | **pipeline_healthy를 수집 상태에서만 결정. 스크리닝 성공만으로 healthy 전환 금지** |
| T-2 데이터로 스크리닝 시 전일 급등/급락 종목 누락 | ⚠️ Medium | T-2 사용 시 텔레그램 경고 + 로그 기록 |
| validate_screening_readiness가 DB 쿼리 실패 시 스크리닝 차단 | ⚠️ Medium | 쿼리 실패 시 기존 파이프라인 의존성 체크로 폴백 |

---

## 5. 최종 의견

**조건부 승인**. 핵심 조건:
1. **pipeline_healthy와 screening_ready 분리**: 수집 실패 시 pipeline_healthy=false 유지는 절대 원칙
2. **이중 실패 시 스크리닝은 허용하되 자동 매매는 차단**: pipeline_healthy=false 상태에서는 반자동 모드에서만 승인 기반 매매 가능
3. **T-2 데이터 사용 시 반드시 텔레그램 경고 발송**

"데이터가 있으니 스크리닝하자"는 올바른 방향이지만, "스크리닝했으니 매매하자"로 이어지면 안 됨. 이 경계선을 pipeline_healthy 플래그가 지켜야 함.
