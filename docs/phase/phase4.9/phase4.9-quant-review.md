## 2. 항목별 검증 결과

### DB 데이터 충분성 검증
- `validate_screening_readiness()`는 좋은 설계
- 검증 항목: 건수(>=1500) + 날짜(T-2 이내) + null 비율(<5%) — 이 3가지면 스크리닝 최소 요건 충족
- **추가 권고**: 소스별 건수도 로깅하면 디버깅에 유용 (data_go_kr: X건, kis_daily: Y건)

### T-2 데이터 품질 영향
- 1차 스크리닝은 전일(T-1) 대비 거래량 변화율, 등락률, 시총을 사용
- **T-2 데이터 사용 시**: 거래량 비교 기준이 하루 밀림 → 당일 급등/급락 감지 불가
- **실제 영향은 제한적**: 1차 스크리닝은 "절대값 기준 필터"(시총 1000억 이상, 거래량 50만주 이상 등)가 주요 필터이므로, 하루 차이로 결과가 크게 달라지지 않음
- **T-2는 비상용으로만 허용**: 정상 운영에서는 T-1만 사용해야 함

### 소스 혼합 영향
- `_fetch_today_and_prev()`은 이미 `data_go_kr OR kis_daily` 필터를 적용
- DB 기반 충분성 검증에서도 동일 소스 필터 사용 → 일관성 있음
- **주의**: validate_screening_readiness()의 소스 필터가 screener의 date_subq와 반드시 동일해야 함

### 팩터 스코어링 영향
- 모멘텀/변동성/거래량 팩터는 최근 5일 데이터를 사용 (`_get_recent_market_data(days=5)`)
- DB 폴백으로 1차 필터는 통과하더라도, 5일 데이터 중 최신 1일이 빠지면 팩터 계산이 부정확할 수 있음
- **실제 위험은 낮음**: 5일 중 1일 누락은 통계적으로 큰 영향 없음. 단, 로깅은 필요

## 5. 최종 의견

**승인**. 통계적 관점에서 DB 기반 의존성 전환은 합리적. 1차 스크리닝의 핵심 필터(시총, 거래량, 등락률)는 절대값 기준이므로 T-1/T-2 차이로 결과가 크게 달라지지 않음. 단, validate_screening_readiness()에서 소스별 건수를 details에 포함하면 운영 시 데이터 품질 추적에 유용함.
