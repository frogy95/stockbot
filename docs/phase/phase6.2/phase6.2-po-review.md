## 항목별 검증 결과

### 1. 옵션 선택: 하이브리드 (A+B)
- **판정**: ✅ 통과
- 옵션 A(14:00 전용)는 08:00 조기 성공 기회를 포기하는 과설계
- 옵션 C(포털 제거)는 market_cap/listed_shares 갱신 경로 소멸로 스크리닝 품질 저하
- 하이브리드가 "빠른 시도 + 안정적 보완"의 실용적 균형

### 2. Sprint 분할
- **판정**: ✅ 통과
- Sprint 1: 핵심 수정 (retry 조건 + 14:00 cron + 알림 강화) — 즉시 운영 안정화
- Sprint 2: 백필 + 관찰성 강화 — 과거 데이터 복구 + 장기 모니터링
- 한 스프린트에 하나의 핵심 목표 원칙 준수

### 3. MVP 범위
- Sprint 1이 MVP: retry 조건 수정만으로도 즉시 효과
- 14:00 cron은 Sprint 1에 함께 넣어야 — 다음 거래일부터 바로 동작해야 의미
- 백필은 Sprint 2로 분리 적절 (과거 데이터는 긴급하지 않음)

### 4. 알림 승급 정책
- **판정**: ⚠️ Sprint 1 필수 포함
- KIS 폴백 연속 N일 시 운영자 인지 필수 — 현재 INFO 알림만으로는 부족
- N=3 권고 (3거래일 연속 = 사실상 포털 장애)
