## 항목별 검증 결과

### 1. 1차 스크리닝 데이터 의존도 (재확인)

| 필드 | KIS 일봉 | 포털 | 스크리닝 역할 | 단순화 후 영향 |
|------|---------|------|-------------|-------------|
| close_price | ✅ | ✅ | 모멘텀 팩터, ATR | 없음 |
| volume | ✅ | ✅ | 거래량 비율 필터 + 팩터 | 없음 |
| high_price | ✅ | ✅ | ATR 계산 | 없음 |
| low_price | ✅ | ✅ | ATR 계산 | 없음 |
| change_rate | ✅ | ✅ | 등락률 필터 | 없음 |
| **market_cap** | **None** | ✅ | **시총 필터 (500억)** | 보정 로직 의존 |
| **listed_shares** | 미갱신 | ✅ (stocks 갱신) | market_cap 보정 | 16:00 수집으로 보완 |

**결론**: 08:00 KIS 수집 시점에서 market_cap은 `listed_shares * close_price`로 보정. 보정 커버리지는 stocks.listed_shares 존재 여부에 의존.

### 2. 시총 필터 보정 커버리지 분석

- stocks.listed_shares: 포털 수집 시 `_upsert_stock`에서 갱신 (data_go_kr.py L175)
- **한 번이라도 포털 수집 성공한 종목** → listed_shares 보유 → 보정 가능
- 프로덕션 11일간 KIS만으로 운영: 포털 마지막 성공일(2026-04-03) 기준 listed_shares 존재
- **보정 불가 종목**: 4/3 이후 신규 상장 + 포털 미수집 = 극소수 (일 0~2건)
- **16:00 포털 수집이 정상 동작하면**: 당일 listed_shares 갱신 → 다음 날 08:00 보정 정확도 최신화

### 3. 단순화 후 스크리닝 흐름

```
08:00 KIS 일봉 수집 → market_data (source='kis_daily', market_cap=None)
  → screener: market_cap=0 → listed_shares * close_price 보정
  → 시총 500억 필터 → 3팩터 스코어링 (OHLCV 기반, 포털 무관)

16:00 포털 보조 수집 → market_data (source='data_go_kr', market_cap=실제값)
  + stocks.listed_shares 갱신
  → 다음 날 08:00 보정 정확도 향상
```

**핵심**: 08:00 시점의 스크리닝 품질은 **전일까지의 listed_shares**에 의존. 16:00 포털 수집은 **다음 거래일 스크리닝 품질 보장**이 목적.

### 4. listed_shares 장기 미갱신 시나리오

| 이벤트 | 빈도 | 영향 | 16:00 포털 수집으로 해결? |
|--------|------|------|----------------------|
| 유상증자 | 연 1~2회/종목 | listed_shares 변동 → 시총 과소/과대 평가 | ✅ 당일 반영 |
| 무상증자 | 연 0~1회/종목 | listed_shares 대폭 증가 | ✅ 당일 반영 |
| 액면분할 | 연 0~3건/전체 | listed_shares 급증 + close 급감 | ✅ 당일 반영 |
| 신규 상장 | 일 0~2건 | listed_shares=NULL → 탈락 | ✅ 당일 16:00 수집 후 반영 |

**결론**: 16:00 포털이 정상 동작하면 listed_shares는 최대 1영업일 지연. 이 지연으로 인한 시총 오차는 **무시 가능 수준**.

### 5. 16:00 포털 수집 범위
- **판정**: 전 종목 수집 권고
- 스크리닝 통과 종목만 수집하면: 다음 날 새로운 종목이 시총 필터를 통과할 수 없음 (listed_shares 부재)
- 전 종목 수집: 기존 `collect_all()` 그대로 → ~10페이지 = ~10 API 호출 (Rate Limit 내)
- **데이터가 말하게 하라**: 모든 종목의 listed_shares를 최신으로 유지해야 스크리닝 모수 왜곡 방지

### 6. 기존 vs 단순화 비교 (스크리닝 품질 관점)

| 항목 | 기존 (하이브리드) | 단순화 | 품질 차이 |
|------|-----------------|--------|----------|
| 08:00 OHLCV | 포털 or KIS | KIS | 동일 (둘 다 같은 데이터) |
| 08:00 market_cap | 포털 성공 시 실제값 | listed_shares 보정 | **미미** (보정 커버리지 99%+) |
| 포털 갱신 시점 | 08:00 시도 + 14:00 보조 | 16:00 정규 | **16:00이 더 안정적** (확실한 시간대) |
| 복잡도 | 높음 (3개 경로, 상태 관리) | 낮음 (2개 경로, 상태 없음) | **단순화 우월** |
