## 항목별 검증 결과

### 1. KIS 08:00 주 경로 전환의 리스크
- **판정**: ✅ 통과
- KIS 일봉 API는 내장 3회 재시도 + 지수 백오프로 안정적
- 11일간 KIS만으로 운영한 실적이 이미 검증됨 (실제 프로덕션에서)
- 포털 "기회주의적 시도"의 성공률이 불확실한 것보다 KIS 직접이 리스크가 더 낮음
- **핵심**: 불확실한 경로보다 확실한 경로가 리스크 관리 원칙에 부합

### 2. market_cap 미갱신 장기 시나리오
- **판정**: ⚠️ 주의 — 모니터링 필수
- 포털에서만 제공하는 필드: market_cap, listed_shares (2개)
- screener.py L406-408: `market_cap=0`이면 `listed_shares * close_price`로 보정 (이미 구현)
- `listed_shares`는 stocks 테이블에 저장되어 있고, 거의 변하지 않음
- **위험 시나리오**:
  - 유상증자: listed_shares 변동 (연 1~2회, 소수 종목)
  - 액면분할: listed_shares 대폭 변동 (연 0~3건)
  - 신규 상장(IPO): listed_shares=NULL → market_cap=0 → 시총 필터 탈락
- **실제 영향**: 16:00 포털 수집이 정상 동작하면 당일 최신 listed_shares로 갱신됨
- **16:00 포털 연속 실패 시**: D-2부터 stocks.listed_shares가 stale → 보정 오차 누적
- **권고**: 16:00 포털 수집이 3거래일 연속 실패 시 텔레그램 WARNING 알림 (단순 카운터, Redis 불필요 — 로그 기반)

### 3. 자동매매 차단 조건 재설계
- **판정**: ⚠️ 재설계 필요
- 기존: KIS 폴백 streak 3일+ → pipeline_healthy=false
- 단순화 후: KIS가 주 경로이므로 "폴백" 개념 자체 소멸
- **신규 차단 조건**: 08:00 KIS 수집 자체가 실패하면 기존 premarket "failed" 상태 → pipeline_healthy=false (이미 동작)
- **추가 경고**: 16:00 포털이 5거래일 이상 연속 실패 시 → listed_shares stale 경고
- 하지만 **자동매매 차단까지는 불필요** — KIS OHLCV가 정상이면 3팩터 스코어링은 영향 없음, 시총 필터만 약간 열화

### 4. 16:00 포털 수집 범위
- **판정**: 전 종목 수집 권고
- 1차 스크리닝 통과 종목만 수집하면: 다음 날 새 종목이 후보가 될 때 listed_shares 부재
- 전 종목 수집: 포털 API는 페이지네이션으로 전체 조회 (기존 collect_all 그대로)
- Rate Limit: 일 1,000건이지만 전 종목 수집은 ~10페이지 = ~10건 (충분)

### 5. 상태 관리 제거의 안전성
- **판정**: ✅ 통과
- portal_fresh: 제거해도 문제 없음 — 08:00에 포털을 호출하지 않으니 "포털 최신성"을 추적할 이유 없음
- streak 카운터: 제거해도 문제 없음 — KIS가 주 경로이므로 "폴백 연속 일수" 자체가 무의미
- 상태가 줄어들면 장애 원인 추적이 쉬워짐 — 리스크 관리 관점에서도 바람직
