## 2. 항목별 검증 결과

### 정보 계층 설계 (✅ 통과)
"핵심 -> 상세" 흐름 원칙이 반영되어 있다. 메인 대시보드에서:
- **1단계 (한눈에)**: 오늘 손익 (큰 숫자), 보유 종목 수, 거래 건수, 엔진 상태
- **2단계 (스크롤/클릭)**: 포지션 상세, 최근 신호, 리스크 상태
- **3단계 (별도 페이지)**: 전체 주문 이력, 스크리닝 상세

### 색상 체계 (⚠️ 주의)
한국 증시 색상 관례를 **정확히** 따라야 한다:
- **빨강 (#EF4444 계열)**: 상승, 수익, 양수 -- 좋은 것
- **파랑 (#3B82F6 계열)**: 하락, 손실, 음수 -- 나쁜 것
- **회색**: 보합, 변동 없음

**주의**: 일반적인 서양식 UX (빨강=나쁨, 초록=좋음)를 절대 적용하지 마라. 한국 트레이더에게 빨강=상승은 본능적 반응이다.

추가 색상 가이드:
- 실전 모드: 빨간 배너/배지 (#DC2626 배경 + 흰색 텍스트)
- 모의 모드: 초록 배너/배지 (#16A34A 배경 + 흰색 텍스트)
- 비상 정지 경고: 노란색/주황색 (#F59E0B)
- 승인 대기: 주황색 배지 (#F97316)

### 실전/모의 구분 UX (✅ 통과, 보강 필요)
최리스크의 "3중 구분" 의견에 동의. 구체적 구현:

1. **고정 상단 배너**: 전체 너비, 40px 높이, 실전=빨간배경/모의=초록배경
2. **사이드바 최상단 배지**: 모드명 + 환경 표시 (예: "실전 | 한투증권")
3. **페이지 제목 옆 인디케이터**: 각 페이지 헤더에 작은 dot 표시

전환 시 UI:
- 전환 확인 모달: "실전 모드로 전환합니다. 실제 자금이 사용됩니다." (빨간색 강조)
- 전환 완료 후 3초간 전체 화면 플래시 (주의 환기)

### 매매 승인 UX (⚠️ 주의)
웹에서의 매매 승인은 **시간 압박 상황**이다 (장중 30초, 마감전 15초). UX 설계:

1. **승인 카드 레이아웃**:
   - 종목명 + 현재가 (크게)
   - 매수/매도 방향 (색상 구분)
   - 신뢰도 바 (0~1)
   - 진입가 / 손절가 / 익절가
   - 타임아웃 카운트다운 (프로그레스 바, 잔여 시간 표시)

2. **승인/거부 버튼**:
   - 승인: 큰 버튼, 파란색 (매수) 또는 빨간색 (매도)
   - 거부: 작은 버튼, 회색
   - 버튼 간격 충분히 (오터치 방지)

3. **알림**:
   - 승인 대기 신호 존재 시 브라우저 탭 제목에 "(1) StockBot" 표시
   - 선택적: 브라우저 Notification API 활용 (사용자 동의 시)

### 네비게이션 구조 (✅ 통과)
사이드바 네비게이션 권고:

```
[모드 배지]
대시보드        (홈 아이콘)
포지션          (차트 아이콘)
주문 현황       (목록 아이콘)
매매 신호       (벨 아이콘 + 대기 수 배지)
스크리닝        (검색 아이콘)
매매 이력       (시계 아이콘)
성과 분석       (차트 아이콘) [Phase 5]
---
설정            (톱니바퀴 아이콘)
```

- 매매 신호 메뉴에 승인 대기 건수 배지 표시
- 활성 페이지 하이라이트
- 사이드바 접기/펼치기 (데스크톱)

### 다크 모드 (✅ 통과)
이미 layout.tsx에 `dark` 클래스 적용. 배경 zinc-950, 텍스트 zinc-100. 트레이딩 대시보드에 적합.

## 4. 리스크 및 대안

1. **색상 혼동 리스크**: 개발자가 서양식 빨강=위험 패턴을 무의식적으로 적용할 수 있다. 색상 상수를 `lib/colors.ts`에 정의하고 직접 색상 코드 사용을 금지해야 한다.
2. **승인 UX 반응 속도**: 폴링 5초 간격이면 신호 발생 후 최대 5초 뒤에 표시된다. 장중 30초 타임아웃에서 5초 손실은 허용 가능하나, 승인 페이지에서는 3초 폴링을 권고.
3. **모바일 대응**: Phase 4에서는 데스크톱 우선이지만, 승인 기능만큼은 모바일에서도 사용 가능해야 한다. 승인 카드를 반응형으로 구현 권고.
