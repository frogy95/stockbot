## 2. 항목별 검증 결과

### 실전/모의 모드 구분 (✅ 통과, 조건부)
한유엑 원칙 "과할 정도로" 구분해야 한다는 데 동의. 추가 요구:
- 실전 모드일 때 **전체 레이아웃 상단에 고정 배너** (빨간색 배경, "실전 거래 중" 텍스트)
- 모의 모드는 초록색 배너 ("모의 거래")
- 배지만으로는 부족. 배너 + 배지 이중 표시 필수.

### 모드 전환 보호 (❌ 재검토)
현재 설계에서 모드 전환(모의<->실전, 반자동<->완전자동)이 단순 PUT API로 되어 있다. **리스크 관점에서 반드시 추가해야 할 보호 장치**:

1. **이중 확인 (Double Confirmation)**: 실전 모드 전환 시 "정말로 실전 모드로 전환하시겠습니까?" + 비밀번호 재입력
2. **장중 전환 차단**: Phase 3에서 확정한 "리스크 설정 장중 변경 불가" 원칙 적용. 거래 환경 전환도 장중(09:00~15:30) 차단
3. **활성 포지션 존재 시 전환 차단**: 보유 포지션이 있는 상태에서 모의<->실전 전환 금지
4. **전환 이력 로깅**: 누가 언제 무엇을 전환했는지 DB 기록 (감사 추적)

### 인증 보안 (⚠️ 주의)
단일 사용자이므로 JWT 토큰 인증은 수용 가능하나:
- **HTTPS 필수**: Cloudflare + Vercel SSL이 이미 적용되어 있으므로 OK
- **토큰 만료 시간**: 24시간 이하로 설정. 브라우저 닫으면 재인증
- **로그인 실패 제한**: 5회 연속 실패 시 15분 잠금 (브루트포스 방지)

### 리스크 상태 표시 (✅ 통과)
메인 대시보드에 리스크 상태 요약 표시 적절:
- 일일 손실 현황 (현재값 / 한도 -3%)
- 비상 정지 임계값 (-4%) 근접도
- 활성 포지션 수 / 최대 한도 (5개)
- 연속 손절 횟수 / 한도 (3회)
- **이 정보는 메인 대시보드에 항상 표시되어야 한다. 숨기면 안 된다.**

### 설정 변경 보호 (⚠️ 주의)
설정 페이지에서 리스크 파라미터(손절/익절/일일한도/비상정지)를 변경할 수 있는데:
- Phase 3에서 확정한 **"장중 리스크 설정 변경 불가"** 원칙을 UI에서도 강제해야 한다
- 장중에는 리스크 관련 설정 입력필드를 비활성화(disabled) + 안내 메시지 표시
- 비리스크 설정(알림 설정 등)은 장중에도 변경 가능

## 3. 파라미터 조정 권고

| 항목 | 원래 설계 | 권고값 | 근거 |
|------|----------|--------|------|
| 모드 전환 보호 | 단순 PUT | **이중 확인 + 장중 차단 + 포지션 체크** | 오조작 방지, Phase 3 원칙 준수 |
| JWT 토큰 만료 | 미설정 | **24시간** | 보안 최소 기준 |
| 로그인 실패 잠금 | 없음 | **5회 실패 시 15분 잠금** | 브루트포스 방지 |
| 리스크 설정 장중 잠금 | 백엔드만 | **백엔드 + 프론트엔드 UI 모두** | Phase 3 확정 원칙 |
| 모드 표시 | 배지만 | **고정 배너 + 배지 이중** | 오인 방지 |

## 4. 리스크 및 대안

1. **가장 큰 리스크: 실전/모의 오인**: 모의 거래인 줄 알고 실전에서 주문을 승인하면 실제 돈이 움직인다. 배너 + 배지 + 색상 테마 3중 구분을 강력 권고.
2. **웹 승인 토큰 보안**: 텔레그램과 동일한 일회용 토큰 방식 적용 필요. 토큰 재사용/위조 방지.
3. **설정 변경 감사 로그**: 모든 설정 변경을 DB에 기록하고 대시보드에서 변경 이력 확인 가능하게 해야 한다 (Phase 4에서 기본만, 상세는 Phase 6).
