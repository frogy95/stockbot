## 2. 항목별 검증 결과

### 프로덕트 관점 판단

1. **시급성**: 매매 신호가 단 한 건도 발생하지 않는 것은 **시스템의 핵심 가치가 동작하지 않는 것**. Phase 7 고도화보다 우선.

2. **옵션 (a) 거부 근거**: "장 종반까지 기다리면 된다"는 논리는 단타 시스템에서 용납 불가. 오전~오후 초반의 매매 기회를 전부 포기하는 것.

3. **옵션 (b) vs (c) 트레이드오프**:
   - (b)는 구현 5분 — 상수 하나 변경. 하지만 "전일 대비 1.2배"는 장 전반부에서도 달성 가능하여 필터 무력화 우려
   - (c)는 구현 30분~1시간 — 시간 계산 로직 추가. 전략 의도를 정확히 보존

4. **권장**: (c)를 정식 구현. 단, **사용자가 오늘 장중 시연을 원하므로** Sprint 문서 작성과 동시에 바로 구현 착수 가능한 규모.

### 범위 판단

- **단일 Sprint 충분**: 수정 파일 1개(`momentum_breakout.py`), 테스트 파일 1개
- **Phase 6.1 (서브 Phase)로 분류**: Phase 7은 별도 목표(고도화)이므로 섞지 않음
- **관찰 기간**: 최소 3거래일 모니터링 후 파라미터 미세 조정 가능성 열어둠

## 4. 리스크 및 대안

- **리스크**: 시간가중 보정은 "오전에 거래량이 적지만 오후에 폭발할 것"이라는 예측을 내포. 실제로는 오전 거래량이 적으면 오후에도 적을 가능성이 높음 -> 이 리스크는 **기존 체결강도/돌파 조건이 필터** 역할을 하므로 수용 가능.
