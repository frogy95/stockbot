# Phase 8.5 — 정프로(PO) 리뷰

> **검토 대상**: Phase 8 Sprint 3 착수 직전, 2차 스크리닝 1종목·신호 0건 교차 단절 문제의 브리지 Phase 제안
> **검토일**: 2026-04-22
> **검토 방식 제약**: 본 리뷰는 phase-planner가 서브에이전트 스폰 도구 부재로 페르소나 기반으로 직접 작성함. 사용자 최종 승인 시 전용 전문가 세션 재검토 권장.

---

## 1. 요약

**판정**: ⚠️ 주의 — 방향은 맞지만 범위 드리프트 경계 필요

사용자 지시의 핵심은 "데이터 축적 대기 중 신호 0건 관찰 시간을 제거"이다. 이건 MVP 철학과 완전히 부합한다 — "동작하는 소프트웨어가 완벽한 문서보다 가치 있다". Sprint 3 DoD("신호 발생 3거래일 연속")가 현 조건에서 **논리적으로 달성 불가능**한 구조라면, 그 DoD를 달성 가능하게 만드는 선제 조치가 먼저다. 그렇지 않으면 Sprint 3은 달성 가능한 조건이 오지 않는 상태에서 무한 대기하게 된다 — 이건 프로덕트 관점에서 데드락이다.

다만 브리지 Phase가 **"이왕 하는 김에 Phase 10.1 전부"**로 부풀려지지 않도록 강력한 scope guard가 필요하다. 사용자 프롬프트에도 "즉시 해소 가능한 문제만 선별, 데이터 축적 불필요"라고 명시했다.

### (B) Phase 8 Sprint 3 DoD 재정의 — ✅ 수용

현 Sprint 3 DoD "신호 발생 3거래일 연속 + 다층 진입 분기 각 1회+"는 다음 조건에서만 달성 가능하다:
- 2차 스크리닝 풀이 충분히 크다 (≥5)
- 시간대별 게이트 통과 경로가 존재한다

현재 두 조건 모두 불만족이므로 **Sprint 3 착수 자체가 논리적으로 불가**다. 따라서 Sprint 3 DoD 자체를 재정의하는 것보다 **Sprint 3 착수 블로커를 Phase 8.5로 해제한다**는 프레이밍이 맞다.

권고: Sprint 3 DoD는 그대로 유지하되 **"Phase 8.5 완료 후 착수"** 명시. Sprint 3 DoD에 "일평균 ≥2건" 같은 **프로세스 기반** 신호수 게이트를 추가.

## 4. 리스크 및 대안

### 리스크 1: 범위 드리프트
- **내용**: "이왕 건드리는 김에" Phase 10.1 항목이 스며들 가능성
- **완화**: Phase 8.5 Sprint 수 **최대 2개**로 고정. 그 이상 나오면 Phase 9로 이관

### 리스크 2: 관찰 기간 단축의 회귀 누락
- **내용**: 1거래일 관찰로는 특정 시간대·종목 조건에서만 발생하는 버그 미발견 가능
- **완화**: 배포 당일 2시간 모니터링 + 자동 롤백 트리거(신호 0건 2거래일 연속 시 Phase 8.5 롤백) 사전 설계

### 리스크 3: 풀 하한 폴백이 품질 저하된 종목 투입
- **내용**: 임계값 미달 종목이 2차 스크리닝 결과로 들어가 전략이 저품질 신호 생성
- **완화**: 폴백 종목은 score 메타데이터에 `fallback=true` 표시, Sprint 3 DoD에서 fallback 종목 신호 비율 모니터링

### 대안: "브리지 Phase 생략, Sprint 3 대기" 대안
- **거부**: 현 조건에서 Sprint 3 DoD 달성 경로 없음. 관찰만 하면서 대기하는 것이 사용자 지시(무의미한 대기 제거)와 정면 충돌
