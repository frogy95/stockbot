## 1. 자동 롤백 안전장치 검증

판정: ✅ 정상 작동, ⚠️ 룰 자체는 보수성 부족

자동 롤백이 04-28 16:10 `auto_rollback_2d_zero_signals` 사유로 발동된 것은 **설계 의도대로 작동**했다는 점에서 긍정적이다. Phase 8.5 사전 리뷰의 D4(연속 3거래일 0건 → 자동 중단) 권고가 운영 단계에서 "연속 2거래일 0건"으로 더 보수적으로 강화되어 적용된 것은 옳은 방향이었다 — 만약 D4 원안(3일 연속)이었다면 04-28 발동이 아닌 04-29까지 가야 했고, 그 사이 LIVE 전환 압박이 누적될 수 있었다.

다만 룰이 **신호 0건이라는 단일 시그널에만 의존**한 점은 둔감하다. 이번 사이클에서 폴백이 4일간 605회 발동했음에도 자동 롤백 트리거에 폴백 발동률·폴백 신호율(M-F2)·tier 다양성(M-S3)이 포함되지 않아, 04-23~04-26 4거래일 동안 "M-S1=1건, M-S3=1종" 같은 명백한 적색 신호를 시스템이 자동으로 잡지 못했다. 사람의 5일 관찰 합산 판정에 의존하는 구조는 LIVE 전환 직전 보호장치로는 부족하다.

너무 민감한 부분은 없었다 — 오히려 1주 전체에서 신호 1건뿐이었고 발동 시점도 늦었다.

## 2. 신호 0건 vs 폴백 605회 위험 해석

판정: 🚨 **시스템 신뢰도 적색 — LIVE 전환 절대 금지 신호**

본 신호 1건/4일 vs 폴백 605회/4일은 두 가지 위험 패턴을 동시에 드러낸다.

**(a) 1차/2차 스크리닝 단절** — 폴백이 605회 발동했다는 것은 **2차 스크리닝 통과 종목이 거의 매일 < 3종목**이었다는 뜻이고, 이는 1차에서 풀이 채워졌음에도 2차 게이트가 사실상 모든 후보를 탈락시키고 있다는 신호다. 즉 "스크리닝 풀=1" 문제를 풀려고 도입한 폴백이 **상시 발동 우회 경로**가 되어버렸다. R-5(폴백 발동 조건: <3종목일 때만)는 의도대로 작동했지만, 그 조건이 거의 항상 참이라는 게 진짜 문제다.

**(b) 폴백 품질 검증 불능** — M-F2(폴백 신호율) "측정 불가"가 가장 위험한 항목이다. 폴백이 605회 풀에 들어왔는데 그 중 신호로 이어진 비율을 산출할 수 없다면, 폴백 메타데이터가 신호 단계까지 전파되지 않거나 로깅 누락이 있다는 뜻이다. **계좌 안정성 관점에서 LIVE 전환 시 폴백 종목이 어떤 손익 분포를 보일지 사전 검증할 데이터가 0**이다. 사전 리뷰 리스크 1(저품질 폴백 종목 일괄 손절) 시나리오가 사후 분석조차 불가능한 상태다.

종합: **시스템이 무엇을 매매할지 예측 불가능한 상태** — LIVE 진입 시 daily_max_loss=-2%·emergency_stop=-3% 한도가 일찍 발동될 위험이 매우 높다.

## 3. Phase 10.1 선결 리스크 요건 (우선순위)

Phase 10.1 착수 전 **반드시** 충족되어야 할 가드레일:

- **P0 (착수 전 즉시 차단 해제 필수)**
  - **G1. 폴백 신호율(M-F2) 산출 가능화**: `signal.fallback=true` 메타데이터를 신호·주문·체결 로그까지 전파. 폴백 종목 별도 PnL 집계 대시보드 카드 필수. 이게 없으면 Phase 10.1 어떤 변경도 검증 불가.
  - **G2. 자동 롤백 사유 다변화**: 단일 "0건 2일 연속" 외에 ① 폴백 발동률 ≥ 50% 일수 3일 연속, ② tier 다양성 1종 5일 연속, ③ 폴백 신호 비중 ≥ 70% 1일 — 세 가지를 OR 조건으로 추가. env 토글로 즉시 비활성 가능하게.
  - **G3. 1차→2차 통과율 회로차단기**: 일별 2차 통과율(폴백 제외) < 10% 3일 연속이면 Phase 10.1 변경분을 자동 비활성화하고 Phase 8.5 폴백을 끈다. 스크리닝 단절을 조기 감지.

- **P1 (착수 전 설계·구현 완료 필수)**
  - **G4. 일일 손실 한도 이중화**: 기존 daily_max_loss=-2% 외에 **폴백 종목 한정 -1% 한도** 별도 적용. 폴백 종목 손실이 본 신호 대비 빠르게 누적될 가능성 격리.
  - **G5. 신호 검증 회로차단기**: Phase 10.1 신규 신호 로직은 기본 `dry_run=true` 배포 → Paper 5거래일 신호 분포 + 백테스트 신호 분포 KS 검정 통과 후에만 LIVE 토글 허용.
  - **G6. 모든 신규 파라미터 env 토글화**: 사전 리뷰 §6 리스크 3 원칙 재확인 — 1줄 env 변경으로 즉시 원복 가능해야 함.

- **P2 (Phase 10.1 첫 스프린트 내 처리)**
  - **G7. 관찰 자동 판정**: 5거래일 관찰을 사람 합산이 아닌 cron + API 단일 엔드포인트(이번 핫픽스에서 추가됨)로 매일 자동 판정·알림.
  - **G8. 폴백 종목 position_size 강제 검증 테스트**: R-2(폴백 50%) 적용을 통합 테스트로 강제. 회귀 시 빌드 실패.
  - **G9. KIS 실거래 가드**: Phase 7.0 LIVE 파라미터(max_position=2, position_size=5%)는 Phase 10.1 어떤 변경에서도 건드리지 않음을 코드 레벨 상수로 잠금.

## 결론 한 줄

자동 롤백 자체는 정상 작동했지만 발동이 늦었고 폴백 품질을 검증할 데이터조차 없는 상태이므로, Phase 10.1 착수 전 P0 가드레일(G1~G3) 셋이 모두 구현·배포되기 전까지 LIVE 전환은 절대 금지한다.
