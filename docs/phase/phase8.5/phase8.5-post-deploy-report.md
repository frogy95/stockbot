### 핵심 진단 (advisor 조언 반영)

1. **Phase 8.5 Sprint 2의 풀 폴백은 코드로는 작동하나 효과가 없다.** 폴백 상한은 `max=5`이나 실제 보강되는 건 1종목. 1차 스크리닝이 이미 희박(355150만 통과 가능)하여 폴백 풀 자체가 비어 있는 구조.
2. **atr_filter는 현 관측에서 100% 거부 사유이지만, N=1 종목 × 1거래일 미만 샘플.** 이 데이터만으로 atr_filter 상한 자체의 문제라고 단정하면 확정 파라미터 #14·#15 거부 근거("자유도 증가 과적합", "데이터 없음")와 동일 논리로 재검토 거부될 것.
3. **ATR_FILTER_PCT = 0.05는 하드코딩** (`backend/modules/trading/strategies/momentum_breakout.py:25`). 이는 Phase 8.5 확정 파라미터 **#23 "모든 파라미터 env 변수화 필수 (최리스크 R-3 — 롤백 즉시 가능)"** 원칙 위반. **Phase 8.5 범위 내 미수행 누락**으로 정의됨.
4. **Phase 8 phase8.md의 LIVE 게이트 DoD(187 라인 "신호 3거래일 연속")는 phase8.5.md의 재정의 DoD("일평균 ≥1, 5거래일 관찰")로 아직 동기화되지 않음.** ROADMAP 대시보드만 업데이트됨. 문서 정합성 갭.

## 3. 전문가 4명 페르소나 검토 (병렬 대신 순차, 독립성 보존)

### 3.1 정프로 (PO) — ⚠️ 조건부 통과

- **통과**: 사용자가 제시한 6개 선택지 중 1(atr_filter hotfix)과 2(Phase 8.7 미니 스프린트)는 **기능적으로 유사**하나 **프로세스 차이가 크다**. Hotfix는 파일 3개/50줄/DB 무변경 요건을 충족해야 하는데, "임계값 변경 + env 변수화 + Redis override + 테스트 + 문서"까지 포함하면 대부분 hotfix 기준 초과.
- **거부**: 선택지 5(Phase 9로 바로 이동)는 MVP 범위 위반. Z-score/VWAP는 3~6개월 데이터 축적 의존, 현 단계에서 의미 없음.
- **거부**: 선택지 4(Sprint 2 먼저)는 Phase 8의 "Sprint 번호 = 실행 순서" 원칙(phase8.md 19행) 파기. 관리 UI가 신호 생성 불능을 해결하지 못함.
- **판단**: 가장 실용적인 것은 **"선택지 3(DoD 재정의)을 phase8.md에 반영"하되, "작업 누락 치유용 얇은 Phase 8.5 Sprint 2.1 핫픽스형 마감 스프린트"**를 추가하여 env 변수화와 atr_filter 관측성만 정돈하는 것. Phase 8.5 Sprint 3이라 부르지 말고 **Sprint 2.5**로 정의하여 "누락 치유"임을 명확히 한다.
- **추가**: 사용자가 이번 주 신호 0건을 경험하는 것은 **PRD 상 문제가 아니다**(Phase 8.6 DoD도 Paper, LIVE 전환 전). 프로세스 파기 비용이 더 크다.

### 3.2 최리스크 (리스크관리) — ❌ atr_filter 임계값 즉시 변경 거부 / ✅ env 변수화만 허용

- **최악 시나리오 관점**: atr_filter 5%를 8%로 올리면 `position_size × leverage × max_adverse_move` 기대손실이 **60% 증가**. 변동성 7~10% 종목은 하루 intraday drawdown -5~-7% 흔함. 현 `daily_max_loss=-2%`, `emergency_stop=-3%`로는 1~2건 손절로 당일 한도 도달.
- **확정 파라미터 #8(폴백 종목 손절 -1.5%)·#10(기본 floor 0.5 유지) 동시 적용 중**. 이 조합으로 이미 "보수 모드"에서 운용 중이라는 전제 하에 하드코딩 부분은 변경이 아닌 **변수화만** 허용 가능.
- **원칙 적용**: "규칙의 예외를 허용하지 않는 엄격함." **5거래일 관찰을 1거래일 미만에 중단하는 것은 Phase 8.5 확정 파라미터 #26 위반.** 이 선례를 허용하면 향후 모든 관찰 기간이 "감"으로 중단된다.
- **허용 가능한 것** (논리적 일관성 유지):
  - (a) `ATR_FILTER_PCT` → `settings.ATR_FILTER_PCT` env 변수화 **(값 불변 0.05)**
  - (b) Phase 8.5 Sprint 1 히스토그램에 atr_filter 분포 추가 (관측성만 보강)
  - (c) **Redis override 인프라**만 미리 준비 (`settings:override:ATR_FILTER_PCT`) — 5거래일 관찰 종료 후 데이터 기반 즉시 조정 가능
- **엄격 금지**:
  - 관찰 중 임계값 실제 변경 ❌
  - Hotfix 명목으로 임계값과 인프라 동시 변경 ❌ (PO와 공동 거부)
  - LIVE 전환을 앞당기기 위한 완화 ❌

### 3.3 박퀀트 (퀀트) — ⚠️ N=1 경고 + 구조적 문제 인정

- **통계적 근거**: 30분 × 1종목 샘플은 **통계적 유의성 없음** (n < 30, 표본 다양성 0). "atr_filter가 진짜 병목"이라고 주장하려면 최소 3거래일 × 10종목 이상 관측 필요.
- **단, 구조적 문제는 인정**: 현재 로그는 **1차 스크리닝 통과 풀 자체가 1~2개**임을 보여준다. 이는 atr_filter 문제가 아니라 **훨씬 상위의 1차 스크리닝 volume_ratio(1.5)·change_rate_min(-2.0) 필터** 또는 **2차 pass_threshold(75.0)** 문제일 가능성이 더 크다.
- **Phase 8.5 Sprint 1이 수집 중인 관측성 데이터 활용 필요**:
  - `metrics:strategy:stage:{date}:{stage}:*` Redis 카운터 → 5거래일 누적 후 stage별 reject 분포 히스토그램 분석
  - `metrics:secondary:score:{date}:{bucket}` → 2차 스크리닝 score 분포 확인 (75.0 임계값이 적정한지)
  - 수집된 데이터 없이 임계값 변경은 **확정 파라미터 #14·#15 거부 시와 동일한 프로세스 위반**
- **단순성 원칙**: "파라미터가 많을수록 과적합 위험." ATR 5% → 8% 변경은 단순 조정이나, 동시에 `min_volume_floor` 동적 분기(3단계) + 폴백 로직이 이미 동시 작동 중. 지금 시점의 재튜닝은 **혼선 변수 3개 중첩**으로 향후 원인 분석 불가.
- **제안**: 5거래일 관찰을 완전히 수행한 뒤, 관측 데이터로 **한 번에** 재튜닝. 미리 env 변수화와 Redis override만 준비(최리스크와 동일 결론).

### 3.4 김단타 (단타) — ✅ 실전적 보완 + 풀 빈약이 진짜 원인

- **실전 관점**: 현재 355150이 유일 통과 종목인 이유는 **1차 스크리닝이 "거래량 급증 + 가격 상승" 조건을 만족하는 종목을 충분히 못 뽑고 있다**는 뜻. 어제 시장이 박스권이면 그럴 수 있다 — **시장 상태 의존**이다. 시스템 문제로 단정 못 함.
- **ATR 7~10% 종목은 단타 관점에서 "진입 금지 구간"이 맞다**. 이런 종목은 매수 후 -3% 손절이 1~2시간 내 발동될 확률이 매우 높음. atr_filter 5% 상한은 **과거 확정된 합리 기준**이다. 사용자가 "ATR 7~10%가 주력"이라고 한 진술은 오해 — 실전 단타 대상은 ATR 2~5% 종목이 주력이어야 한다.
- **단, Phase 8.5 Sprint 1에 atr 분포 히스토그램이 빠져 있다.** reject 상위 종목 리스트(`top-rejects`)는 있으나 `atr_ratio` 히스토그램은 수집 대상이 아님. 이건 Sprint 2 확장 시 **얇게 추가할 가치 있음**.
- **폴백 풀 고갈이 실제 병목**: "폴백후보=1종목 추가" 로그는 1차 스크리닝이 1~2종목만 뽑는다는 뜻. 이걸 해결하려면 atr_filter가 아니라 **1차 스크리닝 임계값 완화** 쪽으로 가야 한다. 그리고 그건 Phase 5.1 확정 파라미터(change_rate_min -2.0)를 다시 건드린다 — **절대 금지 영역** (Phase 5.1에서 한 번 완화했고 다시 손대면 하락 종목 자동매매 금지 원칙 위반).
- **결론**: 5거래일 관찰 완료 → 풀 빈약이 구조적인지 시장 일시적인지 구분 → 구조적이면 Phase 10.1 풀 다양성 과제로 승격. **지금 hotfix로 atr 건드리는 건 엉뚱한 곳을 수술하는 것**.
