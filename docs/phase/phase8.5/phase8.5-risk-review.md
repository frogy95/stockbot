# Phase 8.5 — 최리스크(리스크관리) 리뷰

> **검토 대상**: Phase 8 Sprint 3 전 브리지 Phase 8.5 계획 — 2차 스크리닝 풀 확장 + 게이트 완화
> **검토일**: 2026-04-22
> **검토 방식 제약**: phase-planner가 서브에이전트 스폰 도구 부재로 페르소나 기반으로 직접 작성. 페르소나 원칙 — "리스크 관리 규칙은 절대적, 최악의 시나리오를 기준으로 설계" — 엄격 적용.

---

## 1. 요약

**판정**: ⚠️ 주의 — 조건부 승인, 완화 상한선 엄격

"신호가 안 나온다"는 문제 해결을 위해 스크리닝 풀을 늘리고 게이트를 완화하는 방향은 이해한다. 다만 이 프로젝트는 **LIVE 전환 직전**이다. 완화는 **반드시 LIVE 전환 전 관측 기간**에 충분히 검증되어야 하며, 완화 정도도 **Phase 7.0 LIVE 초기 파라미터(max_position=2, position_size=5%, daily_max_loss=-2%, emergency_stop=-3%)의 보수성과 정합**이 맞아야 한다.

내 가장 큰 우려는 두 가지다:
1. **풀 하한 폴백이 품질 낮은 종목을 매매 대상으로 만든다** — 1차 스크리닝 상위인지 아닌지와 무관하게 절대 리스크 기준(-5% 이하 종목 제외 등) 적용 필수
2. **min_volume_floor 시간대 슬라이딩은 오전 소위험 구간에 진입 폭증 위험** — "거래량 얇은데 돌파"는 가짜 돌파(fakeout) 위험이 높다

## 2. 항목별 검증 결과

### (A-1) 2차 스크리닝 모집단 하한 폴백

**판정**: ⚠️ 조건부 승인

**찬성**:
- 풀=1 구조에서는 어떤 리스크 통제도 무의미 (매매 자체가 안 일어남)
- 폴백 종목에 `fallback=true` 메타데이터가 붙는다면 사후 성과 분리 분석 가능

**필수 조건**:
- **R-1**: 폴백 종목도 **1차 스크리닝은 반드시 통과**해야 함 (1차 미통과 종목 투입 절대 금지)
- **R-2**: 폴백 종목에 대해 **position_size 50%** 강제 (prev_close tier와 동일 수준 — 품질 불확실성 보상)
- **R-3**: 폴백 종목 **전일 대비 -3% 이하** 하락 종목 제외 (하락 종목 매수 금지 Phase 5.1 원칙 계승 — -2.0%보다 보수적)
- **R-4**: 폴백으로 보강된 풀 상한 **5종목** (1차 통과 원래 풀 + 폴백 포함 합산 최대 5)
- **R-5**: 폴백 발동 조건: **원래 2차 스크리닝 통과 < 3종목**일 때만 (pass_threshold=75.0 통과 0~2종목)

### (A-2) min_volume_floor 시간대 슬라이딩

**판정**: ❌ 원안 거부 → ✅ 수정안 승인

**원안 우려**:
- 09:00~11:00 구간 0.3으로 낮추면 전일 대비 30% 거래량으로도 진입 가능
- 오전 소량 거래 + 가짜 돌파 조합은 단타 최악 시나리오 (박스권 상단 찍고 반락)
- Phase 6.1에서 거래량 시간가중 보정을 선형으로 이미 도입했으므로 **MIN_VOLUME_FLOOR는 "절대 바닥"** — 이걸 낮추면 안전장치가 사라짐

**수정안 (승인)**:
- `MIN_VOLUME_FLOOR`는 **0.5 고정 유지**
- 대신 **돌파 강도와 연동된 동적 floor** 도입:
  - `gap_rate ≥ 5%` OR `prev_high 돌파 + current/prev_high ≥ 3%`: floor = 0.4
  - `prev_high 돌파 + 3% 미만`: floor = 0.5 (현재)
  - `prev_close tier`: floor = 0.6 (상향 — 약한 신호에는 더 강한 거래량 요구)
- **시간대 슬라이딩은 금지** — 시간이 흐른다고 거래량 요건이 "약해지는" 건 리스크 관점에서 무근거

### (A-3) prev_close_time_guard 13:00 → 14:00 연장

**판정**: ❌ 거부

**근거**:
- prev_close tier는 본래 "전일 종가 돌파"라는 가장 약한 신호 기준
- 13:00 차단은 Phase 8 Sprint 2 확정(2026-04-22)에서 **최리스크 본인이 요구한 안전장치** — 스프린트 종료 직후 완화는 프로세스상 용납 불가
- 오후 1~2시는 점심 반락 구간, prev_close 기준 매수는 **"하락 저가 매수"**로 변질 가능
- 최소 Phase 8 Sprint 3 LIVE 전환 후 **1개월 실거래 관측** 전까지 이 가드는 건드리지 말 것

**대안**: 13:00 가드는 유지하고, 대신 **prev_high tier의 시간 가드를 명시적으로 없음**으로 확정 (prev_high 돌파는 시간 무관하게 유효). 이게 더 안전한 방향.

### (A-4) 관측성 강화 (stage 분포 + secondary total 히스토그램)

**판정**: ✅ 전면 승인 — **MUST, 가장 먼저 배포**

- 관측성 없이 게이트 완화는 맹목적 완화다
- stage별 탈락 카운트 + 시간대별 분포를 **1시간 단위 로깅 + 대시보드 카드**
- 2차 스크리닝 total_score 분포(0~100 히스토그램 bucket 10개)를 일별 집계

## 3. Sprint 3 DoD 재정의

### 원안 ("신호 발생 3거래일 연속, 다층 진입 분기 각 1회+")

- 현 조건에서 달성 불가 → Phase 8.5 완료 전 Sprint 3 착수 절대 금지

### 리스크 관점 대안 DoD (최리스크 권고)

Phase 8.5 완료 후 Sprint 3 DoD:
- **D1**. Phase 8.5 배포 후 **5거래일 관찰**에서 일평균 신호 ≥ 1건
- **D2**. 5거래일 중 **최소 3거래일**에서 신호 1건 이상 (0건 일수 ≤ 2)
- **D3**. 다층 진입 분기 중 **최소 2개 tier**가 각 1회 이상 발동 (원안 "3개 tier 각 1회"는 gap_open 조건이 자주 안 나와 비현실적)
- **D4**. 신호 0건 일수 연속 3거래일 발생 시 **Sprint 3 자동 중단 + 재검토**
- **D5**. LIVE 전환은 **D1~D3 + Paper 5거래일 핫픽스 0건** 동시 충족 시에만

### 4개 질문에 대한 최리스크 답변

**Q1 (풀 확장 vs 게이트 완화 중 무엇이 먼저인가)**:
- **풀 확장이 절대 우선**. 게이트는 이미 Phase 8 Sprint 2에서 정밀 튜닝 완료. 현 풀=1 상태에서는 어떤 게이트도 의미 없음. 풀이 3~5로 늘어난 후 **게이트는 그대로 두고** 관찰 → 그래도 신호 부족 시에만 게이트 재검토.

**Q2 (min_volume_floor 시간 슬라이딩 형태)**:
- **시간 슬라이딩 전면 거부**. 돌파 강도 연동 동적 floor는 승인 (A-2 수정안 참조).

**Q3 (prev_close_time_guard 13:00→14:00 연장 안전한가)**:
- **불안전**. 거부. LIVE 1개월 관측 후 재논의.

## 6. 리스크 및 대안

### 리스크 1: 풀 하한 폴백의 품질 저하 종목 투입
- **최악 시나리오**: 1차 통과 상위 3종목이 모두 "1차는 통과했으나 2차 기준 크게 미달"인 날, 저품질 종목 3종목이 전략에 투입되어 3건 모두 손절
- **완화**: R-3 (하락 -3% 이하 제외) + R-2 (폴백 종목 position_size 50%) + Sprint 3 D4 자동 중단 트리거
- **최악 손실 한계**: 일일 -2% daily_max_loss, emergency_stop -3% 이미 존재 → 시스템적 상한 유지됨

### 리스크 2: min_volume_floor 동적 floor 구현 버그
- **최악 시나리오**: 조건 분기 버그로 floor=0 적용, 전일 거래량 대비 1% 종목도 통과
- **완화**: 절대 하한 `MIN_VOLUME_FLOOR_HARD = 0.3` 별도 상수로 강제 (어떤 분기든 이 이하는 무조건 차단)

### 리스크 3: LIVE 전환 후 "완화됐던 게이트" 회귀 필요성
- **최악 시나리오**: LIVE에서 손실 누적 시 Phase 8.5 완화사항을 원복해야 하는데 롤백 스크립트 없음
- **완화**: Phase 8.5 각 파라미터 **env 변수화** — `MIN_VOLUME_FLOOR_MODE=legacy|dynamic` 토글. 원복은 env 1줄 변경으로 즉시 가능
