## 항목별 검증 결과

### 1. 데이터 수집 실패 폴백 (❌)

공공데이터포털 08:00 수집 실패 시 1차 스크리닝 불가 → 매매 전체 중단. 반드시 폴백 전략 필요:
- 3회 재시도 (30초 간격)
- 실패 시 전일 market_data 재사용 + 텔레그램 경고
- 2일 연속 실패 시 수동 개입 요청

### 2. 1차 스크리닝 후보 상한 (⚠️)

후보 종목 수에 상한이 없으면 WS 40종목 제한 초과 + 리소스 낭비. **최대 30종목** 설정 (스코어 상위 30).

### 3. 체결강도 최소 누적 시간 (⚠️)

체결 데이터가 충분히 누적되지 않은 상태에서 체결강도 계산은 노이즈. **최소 5분(300초) 누적** 후에만 유효값으로 사용. 미달 시 중립(50)으로 처리.

### 4. 실시간 데이터 지연 대응 (❌)

WS 데이터가 10초 이상 미수신 시:
- 해당 종목 스크리닝 결과 무효화
- 매매 신호 생성 차단 (Phase 3 연계)
- 30초 이상 미수신 시 WS 재연결 트리거

### 5. 레버리지 ETF 분류 (✅)

기존 stocks 테이블의 `stock_type` 필드(`leveraged_etf`, `inverse_etf`)로 구분 가능. 스크리닝 시 별도 필터 적용 확인.
