## 항목별 검증 결과

### 1. Sprint 범위 과다 (Sprint 1)

Sprint 1에 5개 외부 API 수집기 + 스케줄러 + WS 매니저 + 체결강도를 모두 넣으면 범위가 Phase 1 Sprint 2보다 큼. "한 스프린트에 하나의 핵심 목표" 원칙 위반.

**권고**: 3 Sprint로 분할
- Sprint 1: 핵심 수집 (공공데이터포털 + 한투 실시간 + 체결강도 + 스케줄러)
- Sprint 2: 종목 스크리닝 엔진 (1차 + 2차 + 스코어링)
- Sprint 3: 보조 데이터 연동 (DART + 네이버) + 통합 테스트

### 2. DART/네이버 우선순위

DART 재무 데이터와 네이버 센티멘트는 PRD에서 "보조 팩터"로 정의. MVP에서는 스크리닝이 이들 없이도 동작해야 함. Sprint 3으로 분리하면 Sprint 1~2만으로도 독립 배포 가능.

### 3. ETF 별도 수집 필요성

공공데이터포털에서 ETF 미제공 → 한투 REST 개별 조회 필수. 대상 ETF가 ~20개이므로 Rate Limit 문제 없음. Sprint 1에 포함 적절.
