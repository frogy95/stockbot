## 2. 항목별 검증 결과

### 데이터 정합성 (Sprint 1)
- H0STCNT0 필드 미파싱은 **데이터 정합성 결함**. 전략 판단이 잘못된 데이터에 기반하고 있으므로 즉시 수정 대상.
- gap_rate 계산이 항상 0인 현재 상태에서 갭 3%+ 분기는 사실상 사문화 코드. 이 분기의 로직도 `snapshot.high = current_price` → `current_price <= current_price` 항상 False로 버그임.

### 진입 조건 다층화 (Sprint 2)
- **prev_close 돌파 진입 추가 시 리스크 증가 항목**:
  1. 신호 발생 빈도 증가 → 동시 포지션 수 증가 → 일일 손실 누적 가속
  2. prev_close < prev_high이므로 더 낮은 가격에 진입 → 전일 고가까지의 거리가 곧 "추가 상승 가능성"이 아닌 "저항선까지의 거리"
  3. 횡보장에서 false positive 증가

- **필수 안전장치**:
  1. prev_close 돌파 진입의 confidence 상한을 prev_high 돌파보다 낮게 제한
  2. prev_close 돌파 시 position_size를 50%로 축소 (반 포지션)
  3. 신호 증가에 따른 일일 최대 거래 횟수 한도 추가

## 3. 파라미터 조정 권고

| 항목 | 원래값 | 권고값 | 근거 |
|------|--------|--------|------|
| prev_close 돌파 confidence 상한 | 없음 (제한 없음) | 0.75 | prev_high 미돌파 상태에서 과도한 신뢰도 방지 |
| prev_close 돌파 position_size | 100% (일반) | 50% (반 포지션) | 낮은 기준점 진입 시 리스크 반감 |
| 일일 최대 거래 횟수 | 없음 | 10건/일 | 신호 남발 시 과도 매매 방지 |
| 당일 고가 갱신 진입 | 없음 | 금지 (Phase 7.2에서 미도입) | 추격매수 위험 높음, 별도 검증 후 도입 |
| 갭 돌파(3%+) 분기 | breakout_ref = high | breakout_ref = open_price | 갭 상승 후 시가 위에서 유지 = 갭 지지 확인 |

## 4. 리스크 및 대안

- **최대 위험 시나리오**: prev_close 돌파 진입 후 전일 고가 저항에서 반락 → 손절(-2%) 발동
  - 대응: 반 포지션(50%) + 전일 고가 돌파 시 추가 매수(나머지 50%) 2단계 진입 고려
- **리스크**: OHLC 데이터 수정 후 갭 돌파 분기가 활성화되면서 예상치 못한 신호 패턴
  - 대응: Sprint 1 배포 후 최소 2거래일 모니터링 필수 (정프로 동의)
- **규칙**: 기존 리스크 한도(일일 -3%, 비상 -4%, 연속 3회 손절 쿨다운)는 절대 완화 금지
