> **검토 대상**: `docs/phase/phase9/phase9.md` (특히 "데이터 의존성 재검토" 섹션)
> **검토 관점**: 사용자 지시 반영도 / 일정 / 대안 채택 판단

## 요약

✅ **통과** — 사용자 지시("데이터 축적 대기가 정말 필요한지 재검토")를 정면으로 받아들여 3가지 대안(A/B/C) 평가를 수행한 점이 합당. 최종 제안(대안 A + 대안 C 병행)은 현실적이며 MVP 원칙에 부합.

---

## 사용자 지시 반영도 평가 ✅

사용자 원문: **"진짜 데이터가 쌓인 상태에서 하는 게 맞는지는 재검토해"**

재검토 결과 핵심 결론:
| 지표 | 기존 | 재검토 후 |
|------|------|---------|
| VWAP 실시간 | 20거래일 대기 | **당일 장중 누적만 필요 → 즉시 착수** |
| Z-score (total) | 20거래일 대기 | **KIS 백필 + 점진 활성화로 조기 착수** |
| Z-score (buy/sell) | 20거래일 대기 | 유지 (실시간 축적만 가능) |

→ **사용자 지시를 정확히 수용함**. VWAP 불필요 대기 제거, Z-score는 점진 전략.

## 항목별 검증 결과

### 1. 대안 평가의 타당성 ✅

- 대안 A(KIS 백필): 기술적 가능성 확인 + buy/sell 분리 한계 인정 → 현실적
- 대안 B(시뮬레이션): 순환 논리 지적하여 기각 → 퀀트 원칙 준수
- 대안 C(점진 활성화): 가중치 단계(0% → 20% → 50% → 100%)가 수학적으로 건전

### 2. Sprint 분할 ✅

- Sprint 1(Z-score), Sprint 2(VWAP), Sprint 3(백테스트 + API) 병행성 합리
- Phase 8 Sprint 5(DB 수집 인프라)가 선행인 점 명확

### 3. 박퀀트의 "Phase 8 Sprint 5 이관" 권고 검토 ⚠️

박퀀트 리뷰에서 **"Phase 8 Sprint 5(가속도 지표)를 Phase 9 Sprint 0으로 이관"** 권고. 동의.

**수정 권고**:
```
Phase 8 Sprint 5: DB 수집 인프라 + VWAP Redis 누적 시작만 (경량)
Phase 9 Sprint 0: KIS 백필 + 5분봉 가속도 지표
Phase 9 Sprint 1: Z-score 엔진
Phase 9 Sprint 2: VWAP 엔진 + 전략 반영
Phase 9 Sprint 3: 백테스트 + API
```

### 4. 착수 조건 재정의의 적절성 ✅

기존 "20거래일 완전 축적" → "Phase 8 Sprint 5 완료 + 5거래일 축적 + KIS API 조사 완료"로 완화.
가중치 100% 활성화는 여전히 "20거래일" 기준 유지 → **착수와 완전 활성화 분리** 설계 훌륭.

## 리스크 및 대안

1. **KIS 과거 분봉 API가 buy/sell 미제공 시**: 대안 C(점진 활성화)만 단독 사용. 영향도 낮음.
2. **VWAP 기반 전략 반영이 돌파 전략에 도움 안 될 가능성**: A/B 관찰 결과로 Phase 10에서 재조정 가능. Phase 9에서는 일단 활성화.
