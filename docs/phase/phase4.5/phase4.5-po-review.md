## 2. 항목별 검증 결과

### 스케줄 의존성 체인
- **판단**: Must-Have. 오늘 장애의 핵심 원인. 잘못된 데이터로 매매 진행하면 실제 손실 발생
- 선행 실패 시 후속 중지 + 텔레그램 알림이 한 세트로 구현되어야 함

### 수동 트리거 파이프라인
- **판단**: Must-Have. 개별 trigger는 이미 있으나 "장전 전체 재실행"이 없음
- API 한 개(`/collector/trigger/premarket-pipeline`)로 08:00~08:20 전체 재실행

### 프론트엔드 UI
- **판단**: Nice-to-Have로 Sprint 2 분리. API가 있으면 curl/대시보드로도 수동 복구 가능
- Sprint 1에서 백엔드 완성 후 Sprint 2에서 대시보드에 "스케줄러 관리" 탭 추가

### ETF sanity check
- **판단**: 기준 완화 필수. seed 데이터(277) → mst 파싱(878)은 정상적인 데이터 소스 변경
- 최초 적재 시에는 sanity check 스킵 또는 조건부 허용

## 3. Sprint 분할 권고
