## 2. 항목별 검증 결과

### ✅ 통과

1. **`_reconnect()` ConcurrencyError 수정**: 기존 `_receive_task` 미취소는 동시 수신 루프 2개가 동일 WS에서 데이터를 가져가는 상황을 만듦. **주문 중복 실행 가능성**이 있는 치명적 결함. 즉시 수정
2. **가드 조건 `and` -> `or`**: 미연결 상태에서 구독 시도 -> 예외 발생 -> 에러 로그 폭주. `or`로 수정하여 어느 한쪽이라도 비정상이면 차단
3. **`_market_open()` 텔레그램 알림**: 장중 WS 연결 실패를 인지하지 못하면 포지션 모니터링 불가 -> 손절 미작동 -> 무제한 손실 위험. **알림 필수**
4. **KIS REST 재시도/백오프**: 500 에러에 재시도 없이 수집 전체 실패는 과도한 단일 장애점. 지수 백오프 3회 재시도 적절
5. **WS connect open_timeout 추가**: 타임아웃 없는 connect는 이벤트 루프 블로킹 위험. 10초 적절

### ⚠️ 주의

1. **`_market_open_recovery()` 단계적 재시도(09:05/09:10/09:15)**: 3회 재시도 자체는 좋으나, 각 재시도에서 `_market_open()`을 호출하면 **WS 연결이 중복 생성**될 수 있음. 재시도 전 기존 연결 상태를 반드시 확인하고, 연결이 있으면 구독만 복원하는 로직 필요
2. **주말/공휴일 필터 미적용 상태에서의 리스크**: 현재 주말에도 스케줄러가 실행됨. 데이터가 없으므로 무해하게 보이나, `_market_open()`이 주말에도 WS 연결을 시도하면 불필요한 에러 로그 + approval_key 소진 가능. Sprint 1에서 최소한 `_market_open`에는 `is_trading_day()` 가드 추가 권장
3. **`_premarket_collect()` 예외 경로 KIS 폴백 미트리거**: 현재 예외 발생 시 `return 0`으로 종료. KIS 폴백이 트리거되지 않으므로 전체 데이터가 부재한 채로 스크리닝 진입. **1차 스크리닝이 빈 데이터로 실행되면 빈 후보 -> 장중 매매 불가** 상태 발생

### ❌ 재검토

1. **`_reconnect()` 구독 복원 실패 시 수신 루프 처리 (Phase 5.2 미해결 #6)**: Phase 5.2에서 이미 지적했으나 미해결 상태. 구독 복원 중 예외가 발생하면 `_receive_task`가 생성되지 않은 채 `_connected=True`가 됨. **좀비 연결** 상태. Sprint 1에서 반드시 해결해야 함 — 구독 복원을 try/except로 감싸고, 실패 시에도 `_receive_task`는 생성하되 텔레그램 경고 발송

## 3. 파라미터 조정 권고

| 항목 | 원래값 | 권고값 | 근거 |
|------|--------|--------|------|
| KIS REST 재시도 최대 횟수 | 미설정 | **3회** | 장전 수집은 시간 여유 있음. 3회(2+4+8=14초)면 대부분 복구 |
| KIS REST 재시도 대상 HTTP 코드 | 미설정 | **500, 502, 503, 429** | 429(Rate Limit)도 재시도 대상에 포함. 400/401/403은 재시도 무의미 |
| recovery 최대 재시도 | 1회(09:05) | **3회(09:05/09:10/09:15)** | 각 시점에서 연결 상태 먼저 확인. 3회 모두 실패 시 텔레그램 긴급 알림 + pipeline_healthy=false 유지 |
| recovery 최종 실패 시 | 없음 | **텔레그램 긴급 알림** | 3회 recovery 실패 = 장중 전체 실시간 파이프라인 마비. 사용자가 수동 개입해야 함 |
| WS connect open_timeout | 미설정 | **10초** | 동의. 모의/실전 동일 |
| `_reconnect()` 구독 복원 실패 대응 | 수신 루프 미시작(좀비) | **복원 실패해도 수신 루프 시작 + 텔레그램 경고** | Phase 5.2 미해결 #6 해결. 부분 구독이라도 수신이 가능하도록 |
| `_premarket_collect()` 예외 시 KIS 폴백 | 미트리거 | **예외 경로에서도 KIS 폴백 시도** | 예외=포털 완전 실패. KIS 폴백이 있으면 최소한 데이터는 확보 |
