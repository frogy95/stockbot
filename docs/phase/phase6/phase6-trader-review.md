## 2. 항목별 검증 결과

### ✅ 통과

1. **`_reconnect()` ConcurrencyError 수정**: 수신 루프가 2개 동시 실행되면 동일 체결 데이터를 2번 처리 -> 체결강도 2배 계산 -> 잘못된 매매 신호 생성. 단타에서 체결강도는 핵심 지표이므로 즉시 수정 필수
2. **`_market_open()` 알림 추가**: 09:00 WS 연결 실패를 모르면 장 시작 후 30분~1시간 동안 실시간 데이터 없이 방치. **시초가 30분은 변동성이 가장 큰 시간대**이므로 즉시 인지해야 함
3. **`_market_open_recovery()` 연결 상태 직접 확인**: 구독 수가 0이 아니더라도 WS 연결이 끊어져 있으면 데이터는 안 들어옴. 실제 연결 상태를 확인하는 것이 맞음
4. **recovery 단계적 재시도 (09:05/09:10/09:15)**: 09:00~09:30은 시초가 매매의 핵심 시간대. 09:05 한 번 실패하면 09:30까지 대응 불가는 너무 위험. 3회 재시도로 09:15까지 복구 기회 확보
5. **주말/공휴일 필터**: 주말에 실행되면 월요일 데이터가 없어 에러만 발생. 트레이딩 캘린더 연동이 맞음

### ⚠️ 주의

1. **recovery 재시도 중 기존 포지션 보호**: recovery가 09:05~09:15 3번 실행되는 동안 기존 보유 포지션이 있으면 **손절 모니터링이 작동하지 않을 수 있음**. recovery 실패 시에도 기존 포지션에 대한 REST 기반 가격 조회를 고려해야 하나, 이는 이번 Phase 범위를 넘어감 (Phase 5.2 미해결 #2). 최소한 "보유 포지션 있음 + WS 미연결" 상태에서 텔레그램 긴급 알림은 필수
2. **`_premarket_collect()` 예외 시 KIS 폴백 미트리거**: 1차 스크리닝 데이터가 없으면 후보 종목이 0개 -> 장중 매매 기회 전체 상실. 포털 예외 시 KIS 폴백으로라도 데이터를 확보하면 최소한 거래량 상위 종목은 스크리닝 가능
