## 2. 항목별 검증 결과

### ✅ 통과

1. **Phase A (치명적 버그 5건) 우선 처리**: 프로덕션 장애 재발 방지가 최우선. Sprint 1에 배치하는 것이 올바른 판단
2. **Sprint 분할 (A/B/C -> Sprint 1/2)**: Phase A(치명적)를 Sprint 1에, Phase B+C(복원력)를 Sprint 2에 분리. 독립 배포 가능하며 Sprint 1만으로도 프로덕션 안정화 달성
3. **`_reconnect()` ConcurrencyError 수정**: `_receive_task` 미취소 버그는 Phase 5.2에서 미발견된 실질 결함. 즉시 수정 필수
4. **가드 조건 `and` -> `or` 수정**: 논리 오류로 WS 미연결 상태에서 구독 시도가 차단되지 않음. 명백한 버그
5. **`_market_open()` bare exception 알림 추가**: 조용한 실패는 장애 인지를 지연시킴. 텔레그램 알림 필수
6. **`_market_open_recovery()` 연결 상태 직접 확인**: `ws_manager.count`는 구독 수이지 연결 상태가 아님. 의미상 오류

### ⚠️ 주의

1. **Phase 6 범위 재정의 필요**: ROADMAP.md의 Phase 6는 "고도화 + 안정화"로 모바일 반응형, 센티멘트, DART 등 넓은 범위. 이번 작업은 "스케줄러 + WS 복원력"에 한정. Phase 문서에서 ROADMAP Phase 6의 나머지 범위는 Phase 6.1+ 또는 Phase 7로 이관한다고 명시해야 함
2. **주말/공휴일 필터(Phase C #8)의 Sprint 2 배치**: 주말 실행은 비용(Railway 사용량)만 발생시키고 실질 가치 없음. Sprint 1에 넣을 수도 있으나, 기존 핸들러들이 데이터 없으면 무해하게 종료되므로 Sprint 2로 분류해도 무방. 다만 텔레그램 알림이 주말에도 발송되면 혼란 → Sprint 1에서 `_market_open` 알림 추가 시 주의
