## 2. 항목별 검증 결과

### MVP 범위
- 반자동 매매 흐름(스크리닝 -> 신호 -> 승인 -> 주문 -> 포지션) 완성이 이 Phase의 핵심 가치.
- 완전 자동 모드는 Phase 5로 분리된 것이 적절. Phase 3에서는 반자동에 집중.
- 텔레그램 알림/승인을 Phase 3에 포함한 것은 PRD의 Must 기능 커버에 필수.

### Sprint 분할
- 3 Sprint 구성은 적정. 리스크 모듈 선행(Sprint 1)은 최리스크 원칙에 부합.
- Sprint 2(전략+주문+포지션)가 범위가 넓으나, 기존 KIS REST 클라이언트에 주문/잔고 API가 이미 구현되어 있어 실제 작업량은 관리 가능.
- Sprint 3(텔레그램)은 Phase 0.5에서 검증 완료된 API를 사용하므로 리스크 낮음.

### 매매 전략
- 단일 전략(모멘텀 브레이크아웃)으로 MVP를 시작하는 것이 실용적.
- 전략 인터페이스(ABC)를 미리 설계하여 Phase 5+ 확장을 대비하는 것은 적절한 투자.

### 주문 방식
- 시장가만으로 시작하는 것은 심플하나, 김단타의 "최우선 지정가" 권고를 수용하는 것이 좋겠음.
- 슬리피지 리스크를 MVP에서도 최소화해야 사용자 신뢰 확보 가능.

## 4. 리스크 및 대안

- **일정 리스크**: Sprint 2의 범위가 넓음 (전략+주문+포지션). 지연 시 포지션 관리를 Sprint 3로 이동하는 폴백 플랜 준비.
- **모의거래 체결 차이**: 모의거래 체결 로직은 실전과 다름 (Phase 1 김단타 조언). 테스트 시 이 차이를 명확히 문서화.
- **텔레그램 의존성**: 텔레그램 장애 시 웹 승인 폴백 필요하나, 웹 대시보드는 Phase 4. Phase 3에서는 텔레그램 장애 시 자동 만료만 구현.
