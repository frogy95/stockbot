## 2. 항목별 검증 결과

### 조회 데이터 정확성 — ✅ 통과 (핵심 개선)

단타 매매에서 **데이터 정확성은 생명**이다. 기존 구조에서 모의 도메인으로 조회하면:
- ETF 시세가 아예 안 나오거나 (HTTP 500)
- 나오더라도 실전과 다를 수 있다 (모의 서버 시세는 지연/불완전)

실전 도메인으로 조회하면 실제 시장 데이터를 받으므로, 스크리닝/매매 판단의 기반이 정확해진다. 단순히 ETF 수집 실패 문제가 아니라, **전체 매매 판단의 신뢰성** 문제.

### 모의 매매와 실전 데이터 조합 — ✅ 이상적 구조

"실전 데이터로 분석하고, 모의 환경에서 매매한다" — 이것이 모의거래의 올바른 사용법.

기존: "모의 데이터로 분석하고 모의 매매" -> 실전과 괴리가 큰 테스트
수정: "실전 데이터로 분석하고 모의 매매" -> 실전 전환 시 데이터 품질 차이 없음

### 시간대별 Rate Limit — ✅ 문제없음

- 장전 08:00: 공공데이터포털 수집 + ETF 마스터
- 장전 08:15: ETF 시세 수집(inquiry_client) — 881개, 0.07초 간격, 약 62초
- 장중 09:00~15:30: 실시간 WS + 매매(trading_client)

조회와 매매가 시간대별 분리. Rate Limit 충돌 리스크 낮음.

### 데이터 누락 매매 영향 — 기존 분석 유지

- 전일 종가/거래량: 당일 변동률 기준선, 거래량 비교 기준
- 전일 고가: 모멘텀 브레이크아웃 전략의 핵심 진입 조건
- market_data가 오래되면 모든 매매 판단 기준이 틀어짐
- pipeline_healthy=false 유지가 유일한 안전장치

## 4. 리스크 및 대안

### 핵심 리스크
- **오래된 데이터 매매가 데이터 없는 것보다 위험**: 사용자가 정상이라고 착각하기 때문. pipeline_healthy 판정이 정확해야 하는 이유.
- 도메인 분리로 ETF 시세 수집이 정상화되면 "실전 전환 시 ETF 별도 검증 필요" 미해결 사항이 자연 해소.
