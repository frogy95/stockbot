## 2. 항목별 검증 결과

### 근본 원인 재정의 — ✅ 통과

기존: "모의투자 서버 ETF 시세 미지원" -> optional 처리
수정: "도메인 라우팅 설계 결함" -> 조회/매매 환경 분리

**판단**: MVP 관점에서 올바른 방향. optional 처리는 "문제를 덮는 것"이고, 도메인 분리는 "문제를 해결하는 것"이다. 1인 개발이라도 근본 원인을 해결하는 게 장기적으로 유지보수 비용이 낮다.

### Sprint 1 범위 — ⚠️ 주의

Sprint 1에 추가되는 작업:
- `kis_config.py`에 `get_inquiry_environment()` 추가
- `token_manager` 이중 인스턴스 초기화
- `main.py` lifespan 이중 클라이언트 초기화
- `CollectorScheduler` inquiry_client 주입
- 기존 작업 (Dockerfile, 에러 전파, 날짜 폴백 등) 유지

**권고**: Sprint 1 작업 순서를 "1. Dockerfile --reload 제거 -> 2. 도메인 분리 -> 3. 에러 전파 수정" 순으로 명확히 해야 한다. --reload 제거와 도메인 분리가 모두 "파이프라인 정상 동작"에 필수이므로 하나의 Sprint에 넣는 것은 맞다.

### "모의 ETF optional" 파라미터 제거 — ✅ 통과

도메인 분리로 조회는 항상 LIVE 도메인을 사용하므로, 모의 환경에서도 ETF 시세 수집이 정상 동작한다. "모의 optional" 분기 자체가 불필요해진다. 코드 복잡도가 줄어드는 좋은 방향.

### 확정 파라미터 통일 — ✅ 통과

모의/실전 구분 없이 ETF 시세는 항상 required로 통일 — 단순하고 좋다.

## 3. 파라미터 조정 권고

| 항목 | 기존 확정값 | 권고 수정값 | 근거 |
|------|-----------|-----------|------|
| ETF 시세 (모의) | optional | **required (LIVE 도메인 사용)** | 도메인 분리로 모의에서도 정상 수집 |
| ETF 시세 (실전) | required | required (유지) | 변경 없음 |
| financial_data 극소량 | 별도 확인 필요 | Phase 5 이후 이관 (유지) | 24건은 정상일 수 있음 |

## 4. 리스크 및 대안

- **LIVE 도메인 앱키 필수**: 모의 환경에서도 KIS_APP_KEY/SECRET (실전 키)가 있어야 조회 가능. .env.example 업데이트 필수.
- **토큰 2개 관리**: inquiry/trading 토큰 각각 Redis 관리. 기존 token_manager 구조가 환경별 독립이므로 리스크 낮음.
- **일정**: Sprint 1 도메인 분리 추가로 약간의 작업량 증가. 하지만 KISRestClient 내부 수정 없이 인스턴스 2개 생성으로 해결하므로 대규모 변경은 아님.
