## 2. 항목별 검증 결과

### 긴급도 판단
- **매매 시스템이 데이터 없이 운영 불가** — 현재 market_data가 3/27에 멈춰있고, 주식 마스터 0건. 매매 엔진이 돌아도 의미 없는 상태.
- Phase 4.5 Sprint 2(프론트엔드 시스템 관리)보다 이것이 우선. 프론트엔드에서 파이프라인 UI를 만들어도 데이터가 안 들어오면 무의미.

### Sprint 분할 의견
- Sprint 1에서 **Dockerfile --reload 제거 + 에러 전파 수정 + data_go_kr 수집일 로직 검증**을 묶는 것이 맞다. 하나의 목표: "파이프라인이 실제로 데이터를 수집하고, 실패하면 정직하게 실패를 보고한다."
- Sprint 2는 **모의투자 ETF 시세 한계 대응 + 주식 마스터 수집 활성화 + 통합 검증**. 데이터 품질과 커버리지 확장.

### 범위 축소 포인트
- ETF 시세 수집 실패는 "모의투자 KIS API 자체 한계"일 가능성이 높다. **무한 재시도보다 폴백 전략**(공공데이터포털 ETF 시세 대체, 또는 모의투자 환경에서 ETF 시세 수집 비활성화)이 현실적.
- financial_data 24건 문제는 DART API rate limit + 대상 종목 수가 적어서 정상일 수 있음. 별도 Phase에서 다뤄도 됨.

## 4. 리스크 및 대안

- **리스크**: 공공데이터포털 API 자체 지연(당일 데이터 다음날 제공)은 코드로 해결 불가. 수집일 로직이 맞더라도 "데이터 없는 날"은 존재.
- **대안**: data_go_kr 수집 시 기준일 데이터가 실제로 API에서 반환되는지 확인하는 validation 단계 추가. 0건 반환 시 전일로 한 번 더 시도.
- **일정**: Sprint 1은 1일, Sprint 2도 1일 목표. Phase 5 착수는 4/4(금) 이후.
