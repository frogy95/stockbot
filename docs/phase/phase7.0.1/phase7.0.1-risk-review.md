## 2. 항목별 검증 결과

### 장애 영향 분석
- WS 미연결 → 실시간 체결가/호가 수신 불가 → 2차 스크리닝 불가 → 매매 신호 생성 불가
- **완전 자동 모드 상태에서 매매 엔진 무력화** = 수익 기회 전면 상실
- 그러나 **포지션 진입 불가 상태이므로 손실 리스크는 0** (현재는 안전)
- 기존 포지션이 있었다면 실시간 가격 업데이트 불가로 손절/익절 불능 → 치명적
- Phase 7.0 Sprint 1~2에서 가격 갱신 연결을 수정했으므로, WS 장애 시 가격 고정 위험 재발

### 원인 A (IP 화이트리스트) 리스크
- Railway IP는 동적 → 재배포 시 IP 변경 가능
- Static IP 활성화하면 고정되지만, Railway 인프라 변경 시 재할당 리스크 존재
- KIS LIVE API와 WS의 IP 관리가 독립적일 수 있음 (REST는 되는데 WS만 안 되는 이유)

### 원인 B (URL 경로 누락) 리스크
- 공식 예제 모두 `/tryitout` 경로 사용
- 기존 PAPER 환경은 경로 없이 동작 중 → PAPER/LIVE 서버 동작이 다를 수 있음
- PAPER에 경로 추가 시 동작 변경 가능성

## 3. 파라미터 조정 권고

| 항목 | 원래 설계 | 권고값 | 근거 |
|------|----------|--------|------|
| PAPER ws_url 변경 | LIVE와 동시 변경 | **LIVE만 먼저 변경, PAPER는 별도 검증 후** | 기존 안정 환경 보호 |
| Static IP 활성화 | 원인 A 확인 시 | **무조건 활성화** | 원인 A든 아니든, LIVE 운영에 고정 IP는 필수 |
| diagnose 실행 순서 | Railway에서 1회 | Railway에서 1회 + **PAPER 경로 추가 영향 로컬 사전 테스트** | PAPER 깨짐 방지 |

## 4. 리스크 및 대안

### 최악의 시나리오
1. **원인 A + B 동시**: IP 등록 + 경로 추가 모두 필요 → 총 소요시간 증가
2. **KIS IP 등록 반영 지연**: 등록 후 수 시간~하루 소요 가능 → 내일 장 전 해결 불가
3. **PAPER 수정으로 모의거래 환경 파괴**: 기존 테스트/검증 파이프라인 중단

### 비상 대응 계획
- IP 등록 지연 시: KIS 고객센터(1544-5000)에 긴급 반영 요청
- PAPER 깨짐 시: git revert로 즉시 롤백
- 내일 장 전 미해결 시: 수동 복구 API(`/api/v1/collector/trigger/market-open-recovery`) 대기

### 필수 조건
- **diagnose_ws.py 결과 없이 코드 수정 배포 금지** — 원인 미확정 상태에서 수정은 2차 장애 유발 가능
- **PAPER 환경 사전 테스트 필수** — `/tryitout` 추가 후 PAPER에서 먼저 동작 확인
