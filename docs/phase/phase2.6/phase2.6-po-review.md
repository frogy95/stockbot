## 2. 항목별 검증 결과

### Phase 분리 여부
- Phase 2.5의 핫픽스로 처리할 수도 있으나, mst 파서 전면 재작성(상수 전체 교체 + 파싱 로직 변경 + 테스트 전면 재작성)은 핫픽스 범위를 넘음
- **판단**: 별도 Phase(2.6)로 분리하는 것이 적절. 단, 패치성 Phase이므로 단일 Sprint 유지

### MVP 영향
- ETF 마스터 적재는 Phase 3 매매 엔진의 전제 조건
- sanity check가 항상 실패하면 ETF 목록이 DB에 적재되지 않아 전체 파이프라인이 동작 불가
- **판단**: Phase 3 진입 전 반드시 완료해야 하는 블로커

### 범위 통제
- 수정 대상: `kis_master.py` + `test_kis_master.py` (2개 파일)
- 새 기능 추가 없음, 기존 인터페이스(collect/filter_etf/sanity_check) 유지
- **판단**: 범위 적절. 추가 확장(ETN 상세 분류 등)은 Phase 3 이후로 미룸
