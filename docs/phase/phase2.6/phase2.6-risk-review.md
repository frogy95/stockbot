> **검토일**: 2026-03-30
> **검토 대상**: KIS mst 파서 올바른 구현 — 아키텍처 초안

## 1. 요약

| 항목 | 판정 |
|------|------|
| 데이터 무결성 | ⚠️ 주의 — offset 기반 파싱은 포맷 변경에 취약, 방어 로직 필수 |
| ETF/ETN 분류 정확성 | ✅ 통과 — offset 61:63 'EF'/'EN' 방식이 실제 데이터와 일치 |

## 2. 항목별 검증 결과

### 데이터 무결성 리스크
- mst 파일은 KIS가 비공식적으로 제공하는 파일로, 포맷 문서가 공개되지 않음
- offset 기반 파싱은 포맷 변경 시 잘못된 데이터가 DB에 적재될 위험
- **판단**: 파싱 후 반드시 필드 유효성 검증 추가 권고
  - stock_code: 6자리 숫자 패턴 검증
  - 증권구분(61:63): 알려진 값('EF', 'EN', 'ST' 등) 외 값이면 로깅

### ETF/ETN 분류
- Phase 2.5에서 확정한 ETN 별도 분류(stock_type='ETN') 정책 유지
- 'EN' 값은 실제 mst 파일에서 확인 필요 — 확인 전까지는 'EF'만 확정, 'EN'은 추정값으로 처리
- **판단**: ETN 구분값은 실제 다운로드로 확인 후 확정. 확인 불가 시 ETN 필터링은 비활성화

### sanity check
- 기존 로직(최소 200종목, spot-check 5종, 전일 대비 +-10%) 그대로 유지
- 파서 재작성 후 실제 KIS mst 다운로드로 sanity check 통과 검증 필수
- **판단**: 단위 테스트 + 실제 mst 다운로드 통합 검증 모두 수행

## 3. 파라미터 조정 권고

| 항목 | 원래 설계 | 권고값 | 근거 |
|------|----------|--------|------|
| 증권구분 ETF 값 | 'EF' | **'EF' 확정** | 실제 데이터에서 확인됨 |
| 증권구분 ETN 값 | 'EN' (추정) | **실제 확인 후 확정** | 추정값으로 코드에 넣되, 실제 mst에서 ETN 종목 확인 필수 |
| 필드 유효성 검증 | (없음) | **stock_code 6자리 숫자 검증 추가** | 잘못된 offset으로 파싱 시 조기 감지 |
| 알 수 없는 증권구분 처리 | (없음) | **로깅 + 스킵** | 'EF'/'EN' 외 값은 무시하되 로그 기록 |

## 4. 리스크 및 대안

- **리스크 1**: KOSPI/KOSDAQ mst 라인 길이가 다르면 offset 61:63이 KOSDAQ에서도 동일한 필드인지 불확실
  - **대안**: 두 시장 모두 실제 다운로드로 offset 검증. 다를 경우 시장별 offset 분리
  - **심각도**: 중 (잘못된 분류 시 일반 주식이 ETF로 적재될 위험)

- **리스크 2**: CP949 인코딩 특수문자 포함 종목명으로 인한 파싱 오류
  - **대안**: 종목명 파싱 시 UnicodeDecodeError 개별 레코드 단위 처리 (기존 로직 유지)
  - **심각도**: 낮

- **리스크 3**: mst 파일 내 헤더 라인이 존재할 가능성
  - **대안**: 첫 번째 라인에서 stock_code 패턴 검증, 실패 시 헤더로 판단하고 스킵
  - **심각도**: 낮
