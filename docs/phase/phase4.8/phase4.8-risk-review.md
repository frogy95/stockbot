## 2. 항목별 검증 결과

### 리스크 시나리오 분석

| 시나리오 | 현재 대응 | 평가 | 요구 조치 |
|----------|----------|------|----------|
| 포털 전일 데이터 미게시 (장전) | 7일 역순 폴백 → 날짜 오염 | ❌ | KIS 보조 수집으로 전환 |
| KIS API 장애 + 포털 미게시 동시 | 대응 없음 | ❌ | T-2 데이터 사용 폴백 + 매매 중단 알림 |
| 포털 부분 게시 (일부 종목만) | 전량 수집 시도 | ⚠️ | 수집률 임계값 + KIS 보충 |
| KIS Rate Limit 초과 | backoff 재시도 있음 | ✅ | 배치 크기 조정으로 충분 |

### 핵심 안전장치 요구

1. **수집 실패 시 매매 파이프라인 자동 중단**: `pipeline_healthy=false` 유지 — 이미 구현됨
2. **보조 수집 데이터 cross-validation**: KIS로 수집한 데이터가 비정상(종가 0, 거래량 0)이면 제외
3. **수집 소스 태깅**: market_data.source 필드로 "kis_daily" 구분 — 스크리닝 시 소스 혼합 방지
4. **이중 실패 시 텔레그램 긴급 알림**: 포털+KIS 모두 실패하면 즉시 알림

## 3. 파라미터 조정 권고

| 항목 | 원래값 | 권고값 | 근거 |

| KIS 보조 수집 최소 성공률 | — | 80% | 80% 미만이면 보조 수집도 실패로 판정 |

| data_date 최대 허용 지연 | T-2 | **T-1 (보조 수집 포함 시)** | KIS 일봉은 전일 데이터 즉시 제공, T-2까지 허용할 이유 없음 |
| 이중 실패 시 매매 | — | **자동 중단 (pipeline_healthy=false 유지)** | 데이터 없이 매매는 절대 불가 |

## 4. 리스크 및 대안

- **최대 리스크**: KIS 일봉 API가 장전(08:00)에 전일 데이터를 제공하지 않을 가능성 → 사전 검증 필수
- **경감 조치**: Phase 0.5 스타일로 KIS 일봉 API 응답을 장전 시점에 먼저 테스트
- **불가항력 대응**: 포털+KIS 모두 불가 시 T-2 데이터로 스크리닝하되, 매매는 반자동(수동 승인)으로 강제 전환
