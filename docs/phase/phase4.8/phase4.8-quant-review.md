## 2. 항목별 검증 결과

### 데이터 품질 관점

1. **KIS REST `inquire-daily-itemchartprice` API**: 한투 API에서 주식 일봉 데이터를 제공하는 `FHKST03010100` tr_id를 사용하면 과거 일봉(OHLCV) 조회 가능. 이 API는 기간 지정이 가능하여 전일 데이터만 정확히 추출 가능.

2. **포털 vs KIS 데이터 차이점**:
   - 포털: 시가총액(mrktTotAmt), 상장주식수(lstgStCnt) 포함 — KIS 일봉에는 없을 수 있음
   - KIS: 거래대금(acml_tr_pbmn) 포함 — 포털에는 없음
   - OHLCV 핵심 4가지(시/고/저/종가 + 거래량)는 양쪽 모두 제공

3. **스크리닝 팩터에 미치는 영향**:
   - volume_factor: 전일 거래량 필요 → KIS/포털 동일
   - momentum_factor: 최근 N일 종가 필요 → KIS 일봉에서 충분
   - volatility_factor: 최근 N일 고/저/종가 필요 → KIS 일봉에서 충분
   - market_cap: KIS 일봉에서 제공하지 않을 수 있음 → **포털 전용 필드, 별도 처리 필요**

### 혼합 소스 시 주의점

- 포털 데이터(source=data_go_kr)와 KIS 데이터(source=kis_daily)가 같은 날짜에 공존하면, `_fetch_today_and_prev`에서 source 필터가 data_go_kr만 보므로 KIS 데이터가 무시될 수 있음
- **해결**: 포털 실패 시 KIS로 **대체** 수집한 경우, 스크리닝에서 해당 날짜의 데이터를 인식할 수 있도록 source 필터 로직 확장 필요

## 3. 파라미터 조정 권고

| 항목 | 원래값 | 권고값 | 근거 |
|------|--------|--------|------|
| KIS 보조 수집 source 태그 | — | `"kis_daily"` | `"kis_rest"`(ETF용)와 구분 필수 |
| 스크리닝 date_subq source 필터 | `data_go_kr`만 | **`data_go_kr` OR `kis_daily`** | 보조 수집 데이터도 스크리닝에 포함 |
| market_cap 부재 시 처리 | — | **필터 스킵 (market_cap=0이면 시총 필터 면제)** | KIS 일봉에 시총 없으면 0으로 설정, 시총 필터에서 제외하지 않고 별도 처리 |
| 데이터 cross-check | 없음 | **양쪽 모두 있는 종목에서 종가 1% 이상 괴리 시 경고** | 데이터 무결성 모니터링 |

## 4. 리스크 및 대안

- **리스크**: KIS 일봉에 시가총액/상장주식수가 없으면 시총 기반 필터가 작동하지 않음
- **경감**: KIS 현재가 API(`get_stock_price`)에서 시총 정보 추출 가능 여부 확인. 또는 stocks 테이블의 기존 listed_shares로 추정
- **통계적 영향**: 전 종목 중 일부만 KIS로 수집되면 백분위 분포가 왜곡될 수 있으나, 전 종목을 KIS로 수집하면 문제 없음
