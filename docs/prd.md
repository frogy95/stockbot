## 1. 프로젝트 개요

### 1.1 목표

한국 주식/ETF 시장에서 자동 종목 스크리닝, 매매 신호 분석, 주문 실행을 수행하는 단타 자동 매매 시스템을 구축한다. 반자동(추천+승인)과 완전 자동 모드를 환경설정으로 전환할 수 있으며, 웹 대시보드와 텔레그램으로 모니터링/제어한다.

### 1.2 목표 사용자

- **1차 사용자**: 본인 (단독 사용자)
- **2차 사용자**: 없음 (개인 전용 시스템)

### 1.3 배경

- 매매 주기: 단타 (데이트레이딩 vs 스윙 허용 여부는 전문가 확정 필요)
- 대상 시장: 한국 주식 + ETF (KOSPI/KOSDAQ 인버스, 레버리지만 포함)
- 향후 확장: 미국 주식/ETF (MVP에서는 아키텍처만 고려, 구현 제외)

## 2. 핵심 기능

### 2.1 자동 종목 스크리닝

- 전체 시장에서 거래량, 변동성 등 조건에 맞는 종목을 자동 탐색
- 종목별 스코어링 및 순위 매기기
- 스크리닝 결과를 대시보드에서 실시간 확인

### 2.2 매매 신호 분석

- 스크리닝된 종목에 대해 매매 전략 기반 신호 생성
- 신호별 신뢰도(0~1) 및 판단 근거 제공
- 전략 로직은 전문가(단타/퀀트) 자문 후 구체화

### 2.3 매매 실행

- **반자동 모드 (기본)**: 매매 신호 발생 시 텔레그램/웹으로 승인 요청 → 사용자 승인 후 주문 실행
- **완전 자동 모드**: 매매 신호 발생 시 즉시 주문 실행 (알림만 발송)
- 환경설정에서 모드 전환 가능
- 한국투자증권 API를 통한 주문 실행

### 2.4 자금 관리

- 비율 기반 투자: 총 투자금 대비 비율로 건당 투자금 배분 (예: 건당 10%)
- 동시 보유 포지션 수 제한 (전문가 확정 필요)
- 손절/익절 기준 (전문가 확정 필요)

### 2.5 데이터 수집

#### 수집 흐름 (Phase 0.5 검증 결과 반영)

```
장전(08:00)  공공데이터포털 → 전 종목(2,880개) 종가/거래량/시총 일괄 수집 (6회 호출)
             DART → 재무 데이터 (분기 갱신 시)
             네이버 → 뉴스 센티멘트 배치 (보조)
                ↓ DB 기반 1차 스크리닝 → 후보 종목(수십 개) 선정
장중(09:00~) 한투 REST/WS → 후보 종목만 실시간 시세/호가/체결
                ↓ 2차 동적 스크리닝 → 매매 신호
장후(15:30~) 한투 REST → 체결 내역/잔고 정산
```

#### API별 역할

- **공공데이터포털 API**: 장전 1차 스크리닝의 핵심 소스. 전 종목 종가/시가/고가/저가/거래량/시총/상장주식수를 6회 API 호출로 일괄 수집 (ETF 미포함)
- **한국투자증권 API**: 장중 실시간 시세(REST + 웹소켓), 호가, 주문 실행. 1차 스크리닝 통과 종목만 대상
- **Open Dart API**: 재무 기초 데이터(매출/영업이익) — 보조 스크리닝 팩터. 실시간 공시는 지연 불확실하여 제외
- **네이버 검색 API**: 뉴스 센티멘트 분석 — 보조 팩터. 대형주 외 속보 반영 1시간+ 지연으로 속보 용도 부적합
- 추가 정보소스는 전문가 의견에 따라 확장 가능 (단, 연동 전 API 테스트 필수)

### 2.6 모의거래/실전거래 전환

- `TRADING_ENV` 플래그 하나로 일괄 전환 (paper/live)
- 모의/실전별 독립 환경변수: 도메인, APP_KEY/SECRET, 계좌번호, tr_id 접두사
- 모의거래 Rate Limit(초당 1건) 대응 스로틀링 내장
- 대시보드에서 현재 모드 명확히 표시 (실전: 빨간 배지, 모의: 초록 배지)

### 2.7 웹 대시보드

#### 주요 페이지

| 페이지 | 기능 |
|--------|------|
| **메인 대시보드** | 오늘 손익, 보유 종목 수, 거래 건수 요약 |
| **포지션** | 현재 보유 종목, 평균가, 현재가, 미실현 손익 |
| **주문 현황** | 대기/체결/취소 주문 목록 |
| **매매 신호** | 승인 대기 신호 (반자동 모드에서 승인/거부) |
| **스크리닝** | 종목 스크리닝 현황 및 점수 |
| **매매 이력** | 과거 거래 내역 |
| **성과 분석** | 수익률 차트, 기간별 분석, 전략별 성과 비교 |
| **설정** | 매매 설정, 거래 환경, 알림 설정, 인증 관리 |

#### 대시보드 특성

- 다크 모드 기본
- 실시간 업데이트 (폴링 5초 또는 SSE)
- 반응형 (모바일 기본 지표 확인 가능)

### 2.8 텔레그램 봇

#### 알림

- 매매 신호 발생 알림
- 주문 체결 완료 알림
- 일일 마감 리포트 (손익 요약)
- 시스템 오류/경고 알림
- 거래 환경 변경 알림

#### 매매 승인 (반자동 모드)

- 인라인 버튼으로 승인/거부
- 설정 시간 내 미응답 시 자동 만료 (타임아웃 값은 전문가 확정 필요)

#### 조회 명령어

- `/status` — 현재 포지션 요약
- `/today` — 오늘 손익
- `/mode` — 현재 모드 확인
- `/help` — 명령어 목록

#### 보안

- Chat ID 화이트리스트 (환경변수로 관리)
- 승인 요청별 일회용 토큰
- 모드 전환은 텔레그램에서 불가 (웹에서만)

## 5. 시스템 아키텍처

### 5.1 전체 구조

모놀리식 + 모듈 경계 (접근방식 C): 배포는 단일 서버, 코드는 모듈로 분리하여 확장 대비.

```
┌─────────────────────────────────────────────┐
│              AWS Lightsail                    │
│  ┌────────────────────────────────────────┐  │
│  │        Docker Compose                  │  │
│  │                                        │  │
│  │  [Next.js :3000] ◄──► [FastAPI :8000]  │  │
│  │                        │               │  │
│  │                        ├ modules/      │  │
│  │                        │ ├ trading/    │  │
│  │                        │ ├ collector/  │  │
│  │  [Telegram Bot API]◄───│ ├ screening/  │  │
│  │                        │ ├ notifier/   │  │
│  │                        │ └ analyzer/   │  │
│  │  [PostgreSQL :5432]◄───│               │  │
│  │  [Redis :6379]     ◄───│ ├ core/       │  │
│  │                        │ └ api/        │  │
│  └────────────────────────────────────────┘  │
│                                               │
│  외부: 한투 API, 네이버 API, DART API,        │
│        공공데이터포털 API                      │
└─────────────────────────────────────────────┘
```

### 5.3 매매 실행 흐름

```
1. collector → 데이터 수집 (장전/장중/장후 스케줄)
2. screening → 수집 데이터로 종목 스크리닝
3. trading.strategy → 매매 신호 분석
4. [반자동] notifier → 텔레그램/웹 승인 요청 → 사용자 응답 대기
   [완전자동] trading.order → 즉시 주문 실행
5. trading.position → 포지션 업데이트
6. analyzer → 매매 결과 기록/분석
7. notifier → 결과 알림
```

### 5.4 한투 API 토큰 관리

- 백엔드가 독립적으로 토큰 관리 (웹 대시보드 접속과 무관)
- APP_KEY/SECRET은 환경변수, Access Token은 Redis 저장
- 서버 부팅 시 자동 발급, 만료 임박 시 자동 갱신 (스케줄러)
- 토큰 유효기간: ~24시간

## 6. 데이터 모델

### 6.1 주요 테이블

| 테이블 | 역할 |
|--------|------|
| `settings` | 시스템 설정 (모드, 비율, 스케줄, 청산 정책) |
| `stocks` | 종목 마스터 (코드, 이름, 시장유형, market: kr/us) |
| `screening_results` | 스크리닝 결과 (점수, 신호, 상태) |
| `trade_signals` | 매매 신호 (유형, 전략, 신뢰도, 근거) |
| `orders` | 주문 (상태 흐름: pending_approval → approved → submitted → filled) |
| `positions` | 보유 포지션 (매수가, 현재가, 미실현 손익) |
| `trade_history` | 매매 이력 (실현 손익, 수익률, 보유 시간 — 분석용 비정규화) |
| `market_data` | 수집 데이터 (시계열, JSON 저장) |

### 6.2 Redis 캐시

| 키 패턴 | 용도 | TTL |
|---------|------|-----|
| `realtime:{stock_code}` | 실시간 시세 | 5초 |
| `screening:latest` | 최신 스크리닝 결과 | 스케줄 주기 |
| `approval:{order_id}` | 텔레그램 승인 대기 | 설정값 |
| `session:{token}` | 웹 세션 | 24시간 |
| `kis:access_token` | 한투 API 토큰 | ~24시간 |

## 9. 우선순위 (MoSCoW)

| 분류 | 기능 |
|------|------|
| **Must** | 자동 종목 스크리닝, 매매 신호 생성, 반자동 승인(텔레그램+웹), 주문 실행, 포지션 관리, 모의/실전 전환, 기본 대시보드 |
| **Should** | 완전 자동 모드, 성과 분석 차트, 수익률 비교, 일일 리포트 |
| **Could** | 전략별 성과 비교, 뉴스 센티멘트 시각화, 모바일 반응형 |
| **Won't (MVP)** | 미국 주식 거래 (아키텍처만 대비), 백테스팅 (전문가 판단 후), 신용거래, 선물/옵션 |
