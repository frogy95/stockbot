Phase 3 계획 수립 완료 (2026-03-30).

**Why:** Phase 2의 데이터 수집/스크리닝 파이프라인 위에 실제 매매 엔진을 구축. 반자동 매매 흐름(스크리닝 -> 신호 -> 승인 -> 주문 -> 포지션)을 완성하는 핵심 Phase.

**How to apply:**
- Sprint 1: 리스크/자금 관리 (선행 필수, 최리스크 원칙)
- Sprint 2: 모멘텀 브레이크아웃 전략 + 주문 실행
- Sprint 3: 텔레그램 봇 + 반자동 승인

**전문가 검토 결과 주요 변경:**
- 비상 정지: -5% -> -4% (최리스크)
- 레버리지 건당 투자비율: 10% -> 5% (최리스크)
- 레버리지 최대 포지션: 2개 제한 (최리스크)
- 트레일링 활성화: +1.5% 이상 시 (최리스크)
- 당일 청산 강제: 14:50 시장가 (초안 누락, 최리스크+김단타)
- 주문 방식: 시장가 -> 최우선 지정가+3초 폴백 (김단타+정프로)
- ATR 5일 상위 20% 제외 (박퀀트)
- 보합 청산: 진입 30분 후 +1% 미달 (김단타)
- 쿨다운: 30분 내 2연속 손절 시 1시간 (최리스크)
- 골든타임 타임아웃: 20초 (김단타)

**다이어그램 작성 규칙:**
- Mermaid 다이어그램은 반드시 `graph TD` + subgraph 내부 노드 간 `-->` 체이닝으로 세로 배치할 것
- 노드를 subgraph 안에 나열만 하면 가로로 넓어져 가독성이 떨어짐 (사용자 피드백)
- 줄바꿈은 `\n` 사용

**주의사항:**
- 모의거래 체결 로직은 실전과 다름 — 모의에서는 시장가만 사용
- 체결 폴링 30초 내 확인 불가 시 reconciliation 필요
- 텔레그램 장애 시 웹 승인은 Phase 4까지 없음 (자동 만료만)
- 서버 다운 시 14:50 강제 청산 미실행 리스크 — 재시작 시 즉시 처리 로직
