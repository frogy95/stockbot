Phase 5.2: KIS WebSocket 모의 환경 안정화

**Why:** 모의 환경에서 WS 재연결 시 60건(30종목 x 2 tr_id) 구독을 딜레이 없이 한꺼번에 전송하여 서버 과부하 -> 재연결 반복 -> 2차 스크리닝 장중 마비. (rev.2: 구독 수 초과가 아닌 재연결 버스트가 근본 원인)

**How to apply:**
- 단일 Sprint: 재연결 딜레이(0.5초/종목, 핵심 수정) + 환경별 구독 제한(paper=25, live=35) + 재연결 로직(7회, 2초 백오프) + 2차 스크리닝 WS 연동 + 캐시 TTL 10초
- 전문가 4명 검토: 정프로(PO), 최리스크(리스크), 윤에이피(API), 김단타(단타)
- 핵심 파라미터 11건 확정 (rev.2: paper 20->25 상향)
- Phase 6 이관: WS 장애 시 REST 폴백 감시, 장중 동적 우선순위 조정
